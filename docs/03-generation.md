# 03. 생성 — 무엇을 넣고 무엇을 받나

> 강의 목록 · 로드맵 계획 · 강의 자료 · 카드를 만드는 LLM 의 생성 흐름 · 입력 · 재료 · 결과 모양.
> 작업의 수명 · 실패 · 다시 시도는 [04 §4](./04-jobs-and-cost.md#4-만드는-작업), 숙련도 판정은 [02 §5](./02-domain-data.md#5-숙련도--저장하지-않고-계산한다), 입력 화면은 [06 §5](./06-screens.md#5-새로-배우기).
> **프로바이더 · 모델 · 출력 제한 · 프롬프트 문구는 TASK 에서 재 보고 정한다**(README 2026-11-04). 이 문서는 생성 단계 · 재료 · 호출 흐름만 정한다.

## 1. 전체 흐름과 입력

### 1.1 서버가 정한 순서대로 부른다

**만들기마다 단계가 정해져 있고, 서버가 그 순서대로 LLM 을 부른다. LLM 은 도구를 쓰지 않는다**(ADR-118).

| 만들기 | 서버가 준비 | LLM 호출 | 서버가 뒤에 |
|---|---|---|---|
| 강의 목록(새 코스 · 첫 코스 · 다음 코스 · 다시 짜기) | 관련 개념 검색 + 판정(ADR-032) · 로드맵의 코스면 계획 · 앞 코스의 실제 목록 · 뒤 코스의 계획(ADR-051 · ADR-052) | 1번 | 형식 · 10강 상한 검사(ADR-047 · ADR-120) |
| 로드맵 계획(새로 · 다시 짜기) | 관련 개념 검색 + 판정 | 1번 | 형식 검사(ADR-120) |
| 강의 자료 + 카드 | 강의 한 줄의 개념을 사전과 맞춰 판정 지시(ADR-031) | 1번 | 형식 검사(본문 · 카드를 읽을 수 있나 — ADR-163) · 카드의 개념을 사전에 넣는다 — 같은 개념 판정(ADR-048) |

- **한 시도의 채팅 호출은 1번이다** — 출력이 잘리면 이어 쓰기 호출이 정한 횟수까지 더해진다(ADR-127). 고치기 · 다시 만들기 호출은 없다(ADR-023 · ADR-025 · ADR-124). 그 밖에는 임베딩 — 관련 개념 검색(ADR-032) · 카드 개념 판정(ADR-030) — 이 든다.
- **호출 수 상한은 따로 두지 않는다**(ADR-125) — 실패 비용은 자동 다시 시도 횟수(ADR-127)와 한 사람이 동시에 걸 수 있는 수(ADR-104)로 묶는다. 사용자가 누르는 「다시 시도」는 누를 때마다 한 번이다.
- 호출 수 · 비용 · 시간을 미리 알아 크레딧 값과 맞고, 스텁으로 흐름을 시험하기 쉽다. 대신 LLM 이 더 찾아보거나 스스로 고치지 못한다 — 서버가 미리 찾은 재료에서 빠진 것은 모른 채 만든다.

### 1.2 입력 — 새로 배우기

**주제(필수) + 로드맵 체크(선택) + 고르는 항목 2개(필수) + 자유 메모(선택)**(ADR-004). 고르는 항목은 정해진 문구로 LLM 에 넘기고, 그 밖의 취향(깊이 · 실습 · 강의 수 · 참고할 책 등)은 메모로 적는다.

| 입력 | 받는 방식 | 무엇이 달라지나 |
|---|---|---|
| 주제 | 직접 입력 | 무엇을 배우나 |
| 로드맵으로 만들기 | 체크 — 기본은 꺼짐(코스) | 꺼짐: 강의 목록 하나(코스) · 켬: 코스들로 나눈 계획(로드맵)(ADR-008). LLM 이 판단하지 않는다 |
| 지금 수준 | 「처음 배워요」 「기초는 알아요」 「익숙해요」 「기타」(직접 입력) | 강의 목록에 기초를 얼마나 넣나 — 기초부터 · 기초는 짧게 훑고 · 응용 · 심화 중심. **목록을 짤 때만 쓴다** — 강의 자료의 설명 깊이는 숙련도로 정한다(ADR-002) |
| 목적 | 「업무에 쓰려고요」 「면접 준비」 「교양·관심」 「기타」(직접 입력) | 강의 · 카드의 성격 — 업무: 예제 · 실습 · 현업에서 주의할 점 / 면접: 왜 그런가 · 무엇과 비교해 어떤가 · 면접 질문형 카드 / 교양: 비유 · 흐름 |
| 메모 | 직접 입력 | 보기로 담지 못한 취향 |

- **메모는 하나이고 강의 목록과 강의 자료에 모두 쓴다**(ADR-041). 만든 뒤에는 바꾸지 않는다 — 한 코스의 목록과 모든 강의 자료가 같은 메모로 만들어진다. 메모는 결과가 나오기 전에 적는 배우는 사람의 설명이라, 특정 결과를 고치는 다시 짜기 피드백과 다르다(ADR-040).
- **메모는 규칙 안에서만 반영한다**(ADR-039) — 10강 상한 · 확인 질문 · 다음 강의 예고 · 문제풀이 · 객관식 같은 고정 규칙을 넘지 않고, 강의 자료의 설명 깊이도 바꾸지 않는다.
- **로드맵에서 입력이 쓰이는 곳**(ADR-046) — 메모는 로드맵에 하나만 둔다.

| 입력 | 로드맵 계획 | 첫 코스 | 두 번째 코스부터 |
|---|---|---|---|
| 지금 수준 | 쓴다 | 강의 목록에 쓴다 | 쓰지 않는다 — 앞 코스까지의 숙련도가 대신한다 |
| 목적 · 메모 | 쓴다 | 쓴다 | 쓴다 |

## 2. 강의 목록 · 로드맵 계획

**서버가 재료를 넣어 LLM 호출 한 번으로 받는다. 다시 짜기는 같은 호출에 피드백과 이전 목록 · 계획을 더한다**(ADR-120).

**강의 목록 한 줄** — 제목 · 한 줄 설명(이 강의에서 무엇을 배우나) · 다룰 개념(이름 · 한 줄 정의)(ADR-020 · ADR-030). 강의 자료를 만들 때 이 줄이 코스를 짤 때의 의도를 전한다.

**로드맵 계획 한 칸** — 코스마다 제목 · 한두 줄 설명(이 코스를 마치면 무엇을 할 수 있게 되나) · 다룰 개념(ADR-010). 계획 전체에는 로드맵 제목과 설명 한 단락(이 로드맵을 마치면 무엇을 할 수 있게 되나)을 함께 낸다 — 다시 짜면 둘 다 새로 낸다(ADR-167).

**크기**

- 코스는 **최대 10강** — 메모 · 피드백으로도 넘지 않는다(ADR-024 · ADR-047). 로드맵의 코스도 같다.
- 로드맵은 **코스 2개 이상**이고 수의 상한은 없다 — LLM 이 주제에 맞게 정한다. 좁은 주제로 체크해도 2개 이상으로 나눈다(ADR-008).
- 넓은 주제를 체크 없이 만들면 핵심으로 좁혀 코스 하나로 짠다 — 따로 안내하지 않는다(ADR-008 · ADR-102).

**넣는 재료**

| 재료 | 쓰는 곳 | 근거 |
|---|---|---|
| 주제 · 목적 · 메모 | 모두 — 로드맵이면 로드맵의 것을 모든 코스에 | ADR-004 · ADR-046 |
| 지금 수준 | §1.2 의 표대로 | ADR-002 · ADR-046 |
| 관련 개념과 판정 | 모두 — 사용자의 사전에서 의미 검색으로 찾는다. 새 코스 · 로드맵 계획은 주제 · 목적으로, 로드맵의 코스는 계획의 개념으로 찾는다 | ADR-031 · ADR-032 |
| 로드맵 계획에서 그 코스의 개념 | 로드맵의 코스 | ADR-035 |
| 바로 앞 코스의 실제 강의 목록 | 두 번째 코스부터 — 그보다 앞 코스의 목록은 넘기지 않는다 | ADR-051 |
| 뒤 코스들의 계획 | 로드맵의 코스 — 앞 코스의 계획은 넘기지 않는다 | ADR-052 |
| 피드백 · 이전 목록 · 계획 | 다시 짜기 | ADR-037 · ADR-120 |

**숙련도가 하는 일**(ADR-032)

- 잘 아는 개념은 다른 개념과 한 강의에 묶어 적은 자리를 쓰고, 흔들리는 개념에는 강의를 따로 준다. 판정으로 개념을 빼지 않는다(ADR-031).
- 주제와 관련된 흔들리는 개념(로드맵의 앞 코스 · 다른 코스에서 배운 것)을 다시 짚는 강의를 넣을 수 있다 — 로드맵 계획에 없는 개념이어도 된다. 10강 안에서 새 개념과 자리를 나눈다.
- 검색으로 놓친 개념은 배분에 반영되지 않는다 — 강의 자료를 만들 때 바로잡힌다.

**로드맵 계획의 개념과 강의의 개념**(ADR-035)

- 계획에서 코스마다 정한 개념은 그 코스에서 모두 다룬다. 강의에서는 더 잘게 나눌 수 있다 — 예: 계획의 「트랜잭션」을 강의에서는 「격리 수준」 · 「전파」로.
- 바로 앞 코스의 실제 목록으로 앞에서 잘게 나누거나 빼고 더한 개념을 알고 이어지게 짜고(ADR-051), 뒤 코스들의 계획으로 뒤에서 다룰 개념을 미리 끌어오지 않으며 마지막 강의는 다음 코스로 이어지게 짠다(ADR-052).
- 빠짐없이 다뤘는지 서버가 따로 검사하지 않는다.

**피드백 — 다시 짜기**

- 검토 중에만 한다. 고칠 점을 자유 글로 적어 목록 · 계획 전체를 다시 짠다(ADR-007 · ADR-009).
- 그 안의 요청은 어떤 것이든 숙련도로 정한 배분보다 앞선다(ADR-037) — 예: 「1~3강은 이미 알아요」 · 「더 짧게」 · 「이건 따로 강의로」.
- 고정 규칙과 부딪히면 시스템에 없는 것(이미지 · 질문형이 아닌 카드)과 10강 상한만 막는다(ADR-038 · ADR-047).
- 로드맵의 코스를 다시 짤 때 피드백이 계획의 개념을 빼 달라고 하면 뺀다(ADR-036).
- 피드백은 강의 목록에만 쓰고 강의 자료를 만들 때 넘기지 않는다(ADR-040).
- 반영하지 못한 요청은 알리지 않는다 — 결과만 보여 준다. 입력 칸의 미리 안내도 두지 않는다(ADR-045).

## 3. 강의 자료와 카드

**강의를 처음 열 때 그 강의의 자료와 카드를 LLM 호출 한 번으로 함께 받는다 — 본문 뒤에 그 본문의 카드가 온다**(ADR-011 · ADR-013 · ADR-119).

```
서버: 강의 한 줄의 개념을 사전과 맞춰 판정 지시를 만든다(ADR-031)
LLM : 강의 자료 + 카드 — 호출 한 번
서버: 카드의 개념을 사전에 넣는다 — 같은 개념 판정(ADR-048)
```

**넣는 것 — 이것뿐이다**(ADR-123) — 강의 한 줄(제목 · 설명 · 다룰 개념) · 목적 · 메모 · 개념마다 판정 지시. 다시 짜기 피드백은 넣지 않는다(ADR-040). 학습 중에 강의 자료에 바라는 것을 전할 길은 없다.

- **무엇을 다룰지는 목록 한 줄이, 어떻게 다룰지는 메모가 정한다 — 부딪히면 목록 한 줄이 앞선다**(ADR-042). 메모는 예제 언어 · 실습 · 비유 · 참고할 책에만 닿는다. 예: 메모에 「트랜잭션 전파는 빼 줘」를 적어도 목록에 있는 개념은 빼지 않는다.
- 한 번 만든 강의 자료와 카드는 그대로다 — 다시 만들지 않는다(ADR-025).

**강의 자료의 구성 — 고정 뼈대 + 선택 섹션**(ADR-021)

| 뼈대 — 모든 강의 | 담는 것 |
|---|---|
| 이번 강의에서 배울 것 | 목표 한두 줄 + 앞 강의와 어떻게 이어지나 |
| 개념 설명 | 다룰 개념마다 — 판정에 따라 짧게 또는 자세히. 예시는 설명 안에 섞는다 |
| 정리 | 핵심 요약 |

| 선택 섹션 | 붙는 조건 |
|---|---|
| 예시 | 여러 개념을 함께 보여 주는 예제가 필요할 때(LLM 이 판단) |
| 직접 해 보기 | 목적이 「업무」이거나 메모에 실습 요청이 있고, 실습할 수 있는 주제일 때(LLM 이 판단) |
| 현업에서 주의할 점 | 목적이 「업무」일 때 |
| 면접에서 이렇게 물어요 | 목적이 「면접 준비」일 때 |
| 과제 | 메모에 과제 요청이 있을 때 |

- 선택 섹션을 붙일지는 같은 호출에서 LLM 이 정한다 — 서버는 목적 · 메모와 섹션 규칙을 넘길 뿐, 따로 정하거나 확인하지 않는다(ADR-124).
- 넣지 않는 것 — 확인 질문(학습 완료 뒤 카드가 그 역할을 한다) · 다음 강의 예고(순서가 정해져 있고 목록에 보인다).

**표현 수단**(ADR-022)

| 수단 | 쓰는 것 |
|---|---|
| 본문 | 마크다운 — 제목 · 목록 · 강조 · 표 |
| 코드 | 코드 블록 + 문법 강조 |
| 다이어그램 | Mermaid — 흐름도 · 시퀀스 · 클래스 · ER · 상태도 등. 안전 설정 `strict` 를 켠 채로 그린다 |
| 수치 그래프 | Mermaid 의 막대 · 선 차트까지 |
| 수식 | KaTeX |
| 이미지 | 쓰지 않는다 |

- **서버는 Mermaid · KaTeX 문법을 검사하지 않는다**(ADR-117) — 서버 곁에 Node 프로세스를 두지 않는다. 깨진 그림 · 수식은 화면이 그릴 때 라이브러리의 오류 표시를 그대로 보인다 — 고치거나 다시 만들지 않는다(ADR-023).

**카드**

- 질문을 보고 답을 떠올리는 질문형 하나다(ADR-005).
- 카드 하나에 개념이 여러 개 붙을 수 있다 — 비교 · 연결 카드(예: 「TCP와 UDP의 차이는?」)(ADR-033).
- 목적이 「면접 준비」면 면접 질문형 카드(§1.2).

## 4. 프롬프트 공통 규칙

- **고른 값은 정해진 문구로 넘긴다** — 지금 수준 · 목적. 「기타」와 메모는 적은 글 그대로다(ADR-004).
- **숙련도는 판정 지시로 넘긴다** — 숫자를 넘기지 않는다(ADR-031).
- **강의 말투는 하나다** — 강사 선택은 없다(ADR-004).
- **학습과 상관없는 요청을 막는 문구를 넣지 않는다**(ADR-114) — 미리 검사하는 단계도 없다. 결과는 언제나 정해진 형식으로 나오고, 비용은 그 사람의 크레딧 안에서 든다.
- **출력 제한은 여러 번 재 보고 넉넉히 잡는다**(ADR-119) — 출력이 잘리는 것은 주로 우리가 거는 제한 때문이다. 그래도 잘리면 이어 쓴다([04 §4.6](./04-jobs-and-cost.md#46-실패--다시-시도)).

## 5. 숙련도 반영 내역 — LLM 이 적고, 서버는 확인하지 않는다

**강의 목록을 짤 때 LLM 이 숙련도를 어떻게 반영했는지 — 어떤 개념을 짧게 다뤘고 어떤 개념을 다시 짚었는지 — 를 결과에 함께 적는다. 서버는 확인하지 않고 그대로 남긴다**(ADR-121).

- 코스에 딸려 남는다 — 코스를 지우면 함께 지운다(ADR-139 · ADR-140).
- 검토 중인 코스 화면에 몇 개를 짧게 다뤘고 몇 개를 다시 짚었는지 보인다(ADR-090).
- 운영자가 이 기록과 결과를 DB 로 보고 프롬프트 등을 튜닝한다. 실제 배치와 다를 수 있다.

## 6. 호출 기록

**LLM 을 부를 때마다 — 임베딩도 — 호출 기록을 한 줄 남긴다**(ADR-139) — 무슨 만들기였나 · 쓴 토큰 · 비용 · 걸린 시간 · 결과(성공 · 실패의 갈래)와 그 작업 · 사용자. **입력 · 출력 원문은 담지 않는다.**

- 운영자는 이것으로 종류별 크레딧 값(ADR-107)과 한 달 예산(ADR-115)을 맞추고 비용 · 실패를 본다.
- 지우기 · 탈퇴 뒤에도 지우지 않고 작업 · 사람과의 연결만 끊는다([02 §7](./02-domain-data.md#7-지우기--탈퇴--함께-사라지는-범위)). 지운 코스 · 떠난 사람의 비용도 합계에 남는다.
