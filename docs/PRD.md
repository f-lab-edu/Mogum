# PRD: 머금 · Mogum

> **요약 입구다.** 상세와 근거는 [01 개요](./01-overview.md) — 둘이 다르면 01 이 맞다.
> 이름은 [01 §12 용어](./01-overview.md#12-용어)가 단일 출처다.

## 목표

**주제를 정하면 AI 가 커리큘럼과 강의를 만들고, 강의를 끝내면 플래시카드로 복습하며, 복습 결과가 다음 강의의 내용을 바꾸는 학습 서비스.**
AI 로 공부하면 설명은 빨리 얻지만 기억에 남지 않고, SRS 앱은 카드를 직접 만들어야 한다 — 둘을 잇는다. 이미 굳은 개념은 짧게, 흔들리는 개념은 자세히.

> **가설** — 복습 결과를 다음 자료 생성에 반영하면 같은 설명을 반복하는 낭비가 줄고, 흔들리는 개념에 분량이 모인다. 성립 조건은 **숙련도 데이터가 실제로 쌓이는 것**이다. ([01 §2](./01-overview.md#2-문제와-가설))

## 사용자

- 기간을 정해 한 주제를 체계적으로 배우려는 **일반 학습자** — 분야 무관(경제 · 역사 · 법 · 과학 · 자격증 · 프로그래밍).
- 받는 학습은 **개념 · 지식형**만. 연습형(회화 · 실기 · 문제풀이 반복)은 거절한다.
- 강의 · 복습은 **모바일 우선** — 이동 중에 읽고 자투리 시간에 복습한다.
- **정원제 공개** — 정원을 넘으면 대기 명단, 관리자가 승인한다. 공개 전에는 제작자 본인이 먼저 쓴다.

## 제약

| | 값 |
|---|---|
| 개발 | 1인 · 기간과 예산은 유연 |
| 예산 | 월 5만원 기준(LLM 포함) — 예산을 올리면 정원도 올린다 |
| 서버 | AWS EC2 한 대 · 앱 프로세스 하나 |
| 정원 `U_max` | 잠정 약 25명 = min(예산, 측정 용량) |
| 생성 1건 | 강의 자료 = LLM 4회 · 46~62초 · 약 82원 / 커리큘럼 = 1회 · 16~24초 · 약 35원 |

## 핵심 기능

1. **커리큘럼** — 주제 · 기간(1~8주) · 목적 입력 → 강의 목록. 숙련도 전량을 읽어 아는 개념은 빼거나 줄인다. 다시 짜기 3회 · 검토 중 버리기 · 다룰 수 없는 주제는 거절.
2. **강의 자료** — 처음 열 때 1개씩 지연 생성(약 1분 · 비동기 잡). 고정 6섹션 · 강사 말투 · 숙련도별 분량 · KaTeX · mermaid.
3. **플래시카드** — 자료당 최대 10장 · 이해형 · 적용형 위주 · 모범 답안 + 채점 포인트.
4. **복습** — 4단계 자가평가 · FSRS(단기 학습 단계 없음 · 간격 1일 이상) · 오늘의 복습 = 한국 날짜로 오늘 안 · 하루 50장(첫 복습은 한도 밖).
5. **숙련도 · 개념 동일성** — 개념별 `R` · `S` 를 조회 때 계산. 한 줄 정의 임베딩으로 동의어는 합치고 동명이의는 가른다.
6. **비용 통제** — 구조 상한 · 사용자 일일 비용 쿼터 · 진행 중 생성 2개 · 전역 일일 킬스위치.
7. **계정** — 구글 OAuth + 쿠키 세션 · 약관 동의 · 정원 · 대기 명단 · 탈퇴 · 관리자.
8. **화면** — 사용자 8개 + 관리자 1개 + 약관 2장 ([06](./06-screens.md)).

전체 표는 [01 §5](./01-overview.md#5-만들-것).

## MVP 제외 사항

트리거(다시 넣는 조건)가 있는 항목은 *"아직 안 할 것"* 이다 — **조건이 오기 전에 넣지 않는다.** 전체 표와 트리거는 [01 §6](./01-overview.md#6-만들지-않는-것--다시-넣는-조건과-함께).

- 선행 생성(다음 강의 미리 만들기) · 우선순위
- 사전 진단 평가 · 강의 단위 편집 · 자료 개별 재생성
- 객관식 · 빈칸 카드 · 카드 수동 편집
- 통계 대시보드 · 결제 · 소셜 · 모바일 앱 · 다국어
- 이메일 로그인 · 기기 목록 화면 · 관리 UI(정원 · 승인 · 병합은 SQL)
- FSRS 개인화 · 단기 학습 단계 · 그만둔 커리큘럼 카드 제외 · 휴면 자리 회수
- Moderation API · 다크 모드
- 기술: 가상 스레드 · WebFlux · Spring AI · Redis · Kafka · 레이트리미터 · JWT · SSE · 분산 트레이싱 · 멀티모듈

## 성공 기준

- **피드백 루프가 돈다** — 본인이 학습 · 복습한 개념이 다음 자료에서 `BRIEF` · `SKIP` 으로 판정된 사례 1건 이상 + `agent.mastery.coverage` > 0.
- **공개 후** — 실사용자가 커리큘럼을 만들고 3강 이상 학습한다(인원 · 2주 재방문율).
- **콘텐츠 품질 게이트** — 최근 강의 10개 중 치명 결함 1개 이하 · 점수 평균 1.5 이상 ([01 §9](./01-overview.md#9-콘텐츠-품질--채점표와-공개-게이트)).

## 디자인

- 따뜻한 **라이트 테마 하나**(미색 종이 · 먹색 글자) · 포인트 **쪽빛** 한 가지 · 글꼴 **Pretendard**.
- 도구처럼 차분하게 — 가짜 진행 막대 · 모달 · 사용자 화면의 시스템 정보 금지.
- 상세는 [UI_GUIDE](./UI_GUIDE.md), 화면 구조 · 문구는 [06](./06-screens.md).

## 진행 순서

설계 묶음 · 저장소 뼈대(ArchUnit 먼저) → 핵심 경로(커리큘럼 → 자료 → 카드 → 복습, 처음부터 비동기 잡) → 장애 주입 테스트 · **본인 실사용 시작** → 용량 측정 → 정원 → 공개 필수 목록 · 품질 게이트 → 정원제 공개. ([01 §11](./01-overview.md#11-진행-순서))
