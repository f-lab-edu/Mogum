# PRD: 머금 · Mogum

> **요약 입구다.** 상세와 근거는 [01 개요](./01-overview.md) — 둘이 다르면 01 이 맞다.
> 이름은 [01 §12 용어](./01-overview.md#12-용어)가 단일 출처다.

## 목표

**주제를 정하면 AI 가 커리큘럼과 강의를 만들고, 강의를 끝내면 플래시카드로 복습하며, 복습 결과가 다음 강의의 내용을 바꾸는 학습 서비스.**
AI 로 공부하면 설명은 빨리 얻지만 기억에 남지 않고, SRS 앱은 카드를 직접 만들어야 한다 — 둘을 잇는다. 이미 굳은 개념은 짧게, 흔들리는 개념은 자세히.

> **가설** — 복습 결과를 다음 자료 생성에 반영하면 같은 설명을 반복하는 낭비가 줄고, 흔들리는 개념에 분량이 모인다. 성립 조건은 **숙련도 데이터가 실제로 쌓이는 것**이다. ([01 §2](./01-overview.md#2-문제와-가설))

## 사용자

- 한 주제를 자신의 속도로 체계적으로 배우려는 **일반 학습자** — 분야 무관(경제 · 역사 · 법 · 과학 · 자격증 · 프로그래밍).
- 받는 학습은 **개념 · 지식형**만. 연습형(회화 · 실기 · 문제풀이 반복)은 거절한다.
- 강의 · 복습은 **모바일 우선** — 이동 중에 읽고 자투리 시간에 복습한다.
- **정원제 공개** — 정원을 넘으면 대기 명단, 관리자가 승인한다. 공개 전에는 제작자 본인이 먼저 쓴다.

## 제약

| | 값 |
|---|---|
| 개발 | 1인 · 기간과 예산은 유연 |
| 예산 | 월 5만원 기준(LLM 포함) — 예산을 올리면 정원도 올린다 |
| 서버 | AWS EC2 한 대 · 앱 프로세스 하나 |
| 정원 `U_max` | 잠정 약 25명 = min(예산, 측정 용량) |
| 생성 1건 | 강의 자료 = LLM 4회 · 46~62초 · 약 82원 / 커리큘럼 = 1회 · 16~24초 · 약 35원(v5 실험 프롬프트 기준 — 운영 프롬프트로 다시 잰다) |

## 핵심 기능

1. **커리큘럼** — 주제 · 목적 입력 → 순서가 있는 강의 목록(총 1~40강). 강의 수는 주제 · 목적 · 숙련도에 맞춰 정하고, 학습 시점과 속도는 사용자가 정한다. 기간/주당 학습량 입력과 일정 생성은 없다. 주제/목적의 임베딩 검색과 키워드 검색으로 학습자의 관련 개념을 선별하고, 숙련도 판정에 따라 아는 개념은 빼거나 줄인다. 입력 예산을 지키며 검색하지 못한 개념은 상세 설명한다. 다시 짜기 커리큘럼당 하루 3회 · 커리큘럼 완전 삭제(강의 자료 · 학습 기록 · 플래시카드도 삭제, 확인 화면에 명시) · 다룰 수 없는 주제는 거절. ([02 §5.4](./02-domain-data.md))
2. **강의 자료** — 처음 열 때 1개씩 지연 생성(약 1분 · 비동기 잡). 고정 6섹션 · 강사 말투 · 숙련도별 분량 · KaTeX · mermaid.
3. **플래시카드** — 자료당 최대 10장 · 이해형 · 적용형 위주 · 모범 답안 + 채점 포인트 · 이미 아는(`SKIP`) 개념으로는 만들지 않는다.
4. **복습** — 4단계 자가평가 · FSRS(단기 학습 단계 없음 · 간격 1일 이상) · 오늘의 복습 = 한국 날짜로 오늘 안 · 일일 개수 제한 없음. 원하는 만큼 진행하고 중간에 나가도 평가한 내용은 저장된다.
5. **숙련도 · 개념 동일성** — 개념별 `R` · `S` 를 조회 때 계산. 한 줄 정의 임베딩으로 동의어는 합치고 동명이의는 가른다.
6. **비용 통제** — 구조 상한 · 사용자 일일 비용 쿼터 · 진행 중 생성 2개 · 전역 일일 킬스위치.
7. **계정** — 구글 OAuth + 쿠키 세션 · 약관 동의 · 정원 · 대기 명단 · 탈퇴 · 관리자.
8. **화면** — 사용자 8개 + 관리자 1개 + 약관 2장 ([06](./06-screens.md)).

전체 표는 [01 §5](./01-overview.md#5-만들-것).

초기 생성은 주제/목적을 잡 I(`CURRICULUM_INITIAL`)에 먼저 저장하고 성공할 때 단일 커리큘럼 또는 그룹을 만든다. 성공 전에는 빈 커리큘럼/그룹이 없으며 실패 재시도는 같은 잡의 입력/체크포인트/예산을 유지한다. 화면은 잡 ID로 기다린 뒤 결과 유형/ID로 검토에 연결한다([05 §2 · §4](./05-api.md)).

관리자 운영 지표의 성공/실패/회수는 `job_events`에 시점별로 기록한다. 재시도 후에도 과거 실패를 보존하고 작업 전환과 이벤트를 함께 커밋한다. 최근 24시간 실패율은 종결된 실행 기준이며 표본이 없으면 NULL이다([02 §6.9](./02-domain-data.md)).

**넓은 주제의 순차 학습** — 첫 생성 호출에서 LLM이 목표의 일관성/독립적인 하위 목표/선행 관계를 기준으로 단일 또는 그룹을 판단하고 단일 강의 목록 또는 그룹 분할안을 함께 반환한다([03 §2.1](./03-generation.md)). 그룹이면 여러 커리큘럼의 분할안을 제안하고 1단계부터 생성/승인/학습한다. 해당 단계의 모든 강의가 완료되면 다음 단계 생성 버튼을 보여준다. 클릭할 때 최신 숙련도로 다음 단계의 상세 목록을 만들며 자동/일괄 생성하지 않는다. 카드 복습 완료는 다음 단계의 조건이 아니다. 전체 단계/진행 위치를 확인하고 다음 단계로 이어갈 기능은 유지하며, 그룹 화면의 상세 구성은 사용자 결정으로 보류한다([06 §7.6](./06-screens.md)). 기간을 배정하는 후속 학습 플랜과 구분한다.

## MVP 제외 사항

트리거(다시 넣는 조건)가 있는 항목은 *"아직 안 할 것"* 이다 — **조건이 오기 전에 넣지 않는다.** 전체 표와 트리거는 [01 §6](./01-overview.md#6-만들지-않는-것--다시-넣는-조건과-함께).

- 학습 플랜(기간 · 주당 학습량 입력, 예상 완료 기간 · 주차별 일정 · 재조정) — MVP 이후 추가 기능. FSRS 복습 일정은 유지
- 선행 생성(다음 강의 미리 만들기) · 우선순위
- 사전 진단 평가 · 강의 단위 편집 · 자료 개별 재생성
- 객관식 · 빈칸 카드 · 카드 수동 편집
- 통계 대시보드 · 결제 · 소셜 · 모바일 앱 · 다국어
- 이메일 로그인 · 기기 목록 화면 · 관리 UI(정원 · 승인 · 병합은 SQL)
- FSRS 개인화 · 단기 학습 단계 · 휴면 자리 회수
- Moderation API · 다크 모드
- 기술: 가상 스레드 · WebFlux · Spring AI · Redis · Kafka · 레이트리미터 · JWT · SSE · 분산 트레이싱 · 멀티모듈

## 성공 기준

- **피드백 루프가 돈다** — 본인이 학습 · 복습한 개념이 다음 자료에서 `BRIEF` · `SKIP` 으로 판정된 사례 1건 이상 + `agent.mastery.coverage` > 0.
- **공개 후** — 실사용자가 커리큘럼을 만들고 3강 이상 학습한다(인원 · 2주 재방문율).
- **콘텐츠 품질 게이트** — 검증 표본 강의 10개에서 치명 결함 0개 · 점수 평균 1.5 이상 · 항목별 평균 1.0 이상. 치명 결함은 평균 점수로 상쇄하지 않으며, 결함을 발견해 생성 구성을 고쳤으면 새 표본 10개로 재검증한다 ([01 §9](./01-overview.md#9-콘텐츠-품질--채점표와-공개-게이트)).

## 디자인

- 따뜻한 **라이트 테마 하나**(미색 종이 · 먹색 글자) · 포인트 **쪽빛** 한 가지 · 글꼴 **Pretendard**.
- 도구처럼 차분하게 — 가짜 진행 막대 · 모달 · 사용자 화면의 시스템 정보 금지.
- 상세는 [UI_GUIDE](./UI_GUIDE.md), 화면 구조 · 문구는 [06](./06-screens.md).

## 진행 순서

설계 묶음 · 저장소 뼈대(ArchUnit 먼저) → 핵심 경로(커리큘럼 → 자료 → 카드 → 복습, 처음부터 비동기 잡) → 장애 주입 테스트 · **본인 실사용 시작** → 용량 측정 → 정원 → 공개 필수 목록 · 품질 게이트 → 정원제 공개. ([01 §11](./01-overview.md#11-진행-순서))
