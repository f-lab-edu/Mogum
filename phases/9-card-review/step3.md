## 배경

**복습 탭이 곧 복습 화면이다 — 누르면 바로 오늘 복습할 첫 카드가 나온다**(06 §11 · ADR-076). 지금 `/review` 의 자리 화면을 복습 화면으로 바꾼다. 코스 화면의 「이 코스 복습하기」 버튼은 step 4 다 — 이 step 은 그 버튼이 보낼 주소(`/review?courseId={id}`)를 받는 쪽까지 만든다.

## 작업

### 1. 화면 — `frontend/src/pages/ReviewPage.tsx`(짝 테스트 `ReviewPage.test.tsx`)

- `/review` 에 붙인다(지금의 `PlaceholderPage title="복습"` 자리). 탭 첫 화면이다.
- 흐름(06 §11 · ADR-015) — 카드 한 장씩: 질문 → 「답 보기」 → 답 + 평가 버튼 넷(다시 · 어려움 · 좋음 · 쉬움). 버튼마다 그 평가의 다음 간격을 짧게 보인다(「1분」 · 「10분」 · 「3일」 — ADR-170). 숫자 간격을 문구로 바꾸는 규칙(분 · 시간 · 일 · 달 · 년의 경계와 반올림)을 정해 함수 하나에 두고 경계값을 테스트한다.
- **몇 장 남았는지**를 보인다 — 받은 목록에서 아직 평가하지 않은 수. 다 보면 다시 읽어 늘 수 있다(06 §11).
- 평가를 보내면 다음 카드로 간다. **받은 카드를 다 보면 다시 읽는다** — 돌아온 카드(「다시」를 누른 카드 · 앞당겨 보기)가 있으면 이어서 보이고, 없으면 「오늘 복습할 카드가 없어요」(ADR-164).
- **탭을 떠났다 돌아오면 다시 읽는다**(06 §15.1) — 보던 카드 · 답 펼침은 기억하지 않는다. 들어올 때마다 서버에서 새로 읽고, 캐시된 옛 목록을 먼저 보이지 마라 — 이미 평가한 카드가 다시 보이면 안 된다.
- 요청 중에는 평가 버튼 · 지우기 버튼을 잠그고 같은 순간의 중복 제출도 막는다(§13 의 학습 완료 방식). 서버는 중복 막기 장치가 없다.
- 평가 실패 — 서버 문구를 그대로 보이고(§2.5) 그 카드에 머문다. step 2 의 「지금 볼 카드가 아님」 거절이면 문구를 보이고 목록을 다시 읽는다. `NOT_FOUND`(그 사이 지워진 카드)도 다시 읽는다.
- 평가 · 지우기가 성공하면 코스 읽기 캐시를 무효화한다 — 코스 화면의 「오늘 복습할 카드 수」가 바뀐다(§13 처럼 즉시 다시 읽지 않고 그 화면을 열 때 읽는다).
- 카드 없음(06 §11 · 시안 16) — 「오늘 복습할 카드가 없어요」와 모구미. **축하 모구미는 아직 없다**(design README 이미지 표 — 「요청」) — §5 의 책 읽기 사본을 자리 이미지로 쓰고, 표의 상태는 그대로 둔다.
- 읽기 실패 — `FailureNotice` 에 무엇이 안 됐나 · 서버 문구 · 「다시 시도」(§2.5).

### 2. 코스로 거르기 — `/review?courseId={id}`(ADR-172 · 06 §11)

- 쿼리가 있으면 step 1 읽기에 코스 ID 를 넘겨 그 코스의 카드만 보이고, 같은 화면에 코스 제목을 보인다(응답의 코스 제목).
- 다 보면 「이 코스는 오늘 복습할 카드가 없어요」와 전체 복습으로 가는 버튼(`/review`). 거른 읽기가 처음부터 비어도 같다.
- 아래 탭 바의 「복습」을 누르면 전체 복습이다 — `/review` 로 가면 쿼리가 없어진다. 주소가 바뀌면 상태를 새로 시작한다(`App` 의 `key={pathname}` 방식은 쿼리를 보지 않는다 — 쿼리가 바뀔 때도 새로 시작하는지 테스트로 확인한다).
- 남의 코스 · 없는 코스(`NOT_FOUND`)는 읽기 실패와 같이 보이고 전체 복습으로 가는 길을 둔다.

### 3. 카드 지우기(ADR-065 · 06 §2.7)

- 카드에 「카드 지우기」를 둔다(답이 틀렸거나 질문이 모호할 때). 누르면 **확인을 펼쳐** 무엇이 사라지는지 알린다 — 이 카드와 이 카드의 복습 기록이 사라지고 되돌릴 수 없다는 것. 문구는 06 §2.7 · ADR-065 에 맞춰 정한다(「숙련도에서도 빠진다」는 사용자에게 말할지 정한다 — 숙련도는 아직 화면에 없다).
- 확인 펼침은 처음 만드는 공통 모양이다(UI_GUIDE §6) — 이 화면 안에 두되, 뒤 TASK(코스 지우기 · 탈퇴)가 같은 모양을 쓸 수 있게 공통 컴포넌트로 둘지 정하고 UI_GUIDE 에 적는다. 확인 · 취소 두 버튼, 포커스 이동, 취소하면 그대로.
- 지운 뒤 다음 카드로 간다(남은 수가 하나 준다).

### 4. 시안 · 범위

- 시안은 방향이다 — 베끼지 않고 UI_GUIDE §2 · §3 의 토큰 · 공통 컴포넌트로 맞춘다. 영역 순서와 가장 강조할 것(카드 · 평가 버튼)을 시안에서 가져온다. 새 토큰 · 컴포넌트가 필요하면 더하고 UI_GUIDE 에 적는다.
- 평가 버튼 넷은 휴대폰 폭(390px)에서 한 줄 또는 2×2 로 눌리기 쉬운 크기(최소 44px)로 둔다.
- 오류 code · 간격의 원래 숫자 · FSRS 상태 · 카드 출처를 보이지 마라(06 §2.6 · §11).

### 5. 시험 — `ReviewPage.test.tsx` · `App.test.tsx`

- `fetch` 대역으로: 첫 카드 질문 → 답 보기 → 버튼 넷의 간격 문구 → 평가 요청 본문 → 다음 카드 · 남은 수 → 받은 목록 끝에서 다시 읽기(돌아온 카드가 이어짐 / 비면 카드 없음) · 요청 중 잠금 · 같은 순간의 두 번 누르기에 요청 하나 · 평가 실패 문구와 머묾 · 「지금 볼 카드 아님」 · `NOT_FOUND` 에서 다시 읽기 · 지우기 확인 펼침 → 취소 / 확인 → 요청 → 다음 카드 · 지우기 실패 · 코스 거르기(쿼리 전달 · 코스 제목 · 끝의 문구와 전체 복습 버튼 · 탭으로 전체 복습) · 다시 들어올 때 새로 읽음 · 읽기 실패와 다시 시도 · 오류 code 가 보이지 않음 · 간격 문구 함수의 경계값.
- `App.test.tsx` — 실제 라우터로 탭 바의 「복습」 → 복습 화면.

### 6. 문서 — 구현으로 정해진 사실만

- `docs/UI_GUIDE.md` — 복습 탭 절을 새로 더한다(배치 · 상태별 구성 · 간격 문구 규칙 · 확인 펼침 · 캐시 · 모구미 자리 이미지). §6 의 「확인 펼침」을 정한 사실로 바꾸고, §7 의 「홈·복습·내 정보는 제목 한 줄의 자리」 문장에서 복습을 뺀다.
- `docs/design/README.md` 이미지 표의 「복습 카드 없음」 자리 — 상태는 「요청」 그대로 두고 고치지 마라.

   - 시스템 정보(오류 code · FSRS 상태 · 원래 숫자)와 06 이 막은 것(카드 출처 · 단축키 · 스트릭 · 통계)이 없는가?

   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약"`. 담을 것: 화면 · 훅 파일 · 간격 문구 규칙 · 확인 펼침 컴포넌트(뒤 TASK 가 쓴다) · 코스 거르기 주소 · 캐시 무효화 키 · 화면 테스트 수(전후)

## 금지사항

- 코스 화면의 「이 코스 복습하기」 버튼을 만들지 마라. 이유: step 4 의 범위다.
- 홈의 「오늘 복습」 칸 · 스트릭(「스트릭 유지 중」 등)을 만들지 마라. 이유: SCHEDULE §3 상 홈 · 크레딧 TASK(11)에서 만들고, 스트릭은 홈에만 둔다(ADR-097).
- 시안의 카드 출처(코스 · 강의) · 「예정 간격」 · 단축키(Space · 1~4) · 알고리즘 이름 · 학습 통계 · 포인트 · 오늘 완료 수 · 「04:00 AM 갱신」 · 「다른 코스 학습하러 가기」 · 새로 배우기 입구를 만들지 마라. 이유: design README 「06 과 다른 곳」 — 06 §11 을 따른다.
- 판단 기준(핵심 포인트) · 답 입력 · LLM 채점 · 빈칸 · 객관식 · 카드 편집 · 직접 추가 · 오류 신고 · 카드별 복습 멈추기 · 카드 다시 만들기를 만들지 마라. 이유: 06 §11 「두지 않는 것」(ADR-005 · ADR-015 · ADR-064 · ADR-065).
- 예정과 상관없이 코스의 카드를 다 보는 방식을 만들지 마라. 이유: 06 §7 · ADR-172.
- 모구미 이미지를 그리거나 새로 만들지 마라. 이유: 모구미는 사용자가 만든다(design README) — 자리 이미지로 진행한다.
- 서버 코드(`backend/`)를 고치지 마라. 이유: step 1 · 2 가 API 를 정했다. 화면에 필요한 칸이 없으면 `blocked`.
- 계약 문서(규칙 문장 · ADR · `AGENTS.md` 금지 목록 · README)의 규칙을 고치지 마라. 이유: phase 전에 정해 커밋했다. 어긋나면 `blocked`.
- 커밋하지 마라. 이유: Claude 리뷰가 승인한 뒤 하네스가 커밋한다.
- 기존 테스트를 깨뜨리지 마라
