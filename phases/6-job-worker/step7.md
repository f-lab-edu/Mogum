## 배경

만드는 동안 사용자가 보는 화면이다. 이 phase 에서는 운영에 처리기가 없어 실제로 작업이 생기지 않는다 — 화면은 작업 주소로 열리고, 시험은 API 를 흉내 내어 한다. 홈의 「만드는 중」 · 새로 배우기 같은 입구는 뒤 TASK 가 만든다.

**계약 문서(06 §6 · 05)는 이 phase 전에 정해 커밋했다. 코드가 계약과 어긋나면 코드를 계약에 맞추고, 맞출 수 없으면 `blocked` 로 멈춰라. 06 의 규칙 문장을 고치지 마라.**

## 작업

### 1. 화면 — `frontend/src/pages/`

- 주소는 작업 ID 를 담는다(예: `/jobs/:jobId`). step 6 의 틀 안이고, 탭에서 들어간 화면이라 위 바에 뒤로 가기 + 제목이다.
- 작업 읽기를 **정한 간격으로 다시 읽는다**(TanStack Query). 간격은 이 step 이 정해 05 §5 에서 옮겨 적는다. 성공 · 실패가 되면 다시 읽기를 멈춘다.
- **보이는 것**(06 §6) — 시안의 구조(모구미 → 무엇을 만드는 중 → 상태 한 줄 → 떠나도 된다는 안내)를 따른다.
    - 무엇을 만드는 중인지 — 새로 배우기면 주제 · 수준 · 목적(02 §8.7 의 화면 글, 기타면 적은 글), 그 밖이면 응답의 제목(강의 · 코스 · 로드맵).
    - 상태 한 줄 — `QUEUED` 는 「차례를 기다리고 있어요」, `RUNNING` 은 종류로: 코스 · 로드맵의 코스 · 코스 다시 짜기는 「강의 목록을 짜고 있어요」, 로드맵 · 로드맵 다시 짜기는 「로드맵 계획을 짜고 있어요」, 강의 자료는 「강의 자료를 만들고 있어요」(06 §6).
    - 「이 화면을 떠나도 계속 만들어요. 홈에서 다시 열 수 있어요.」
- **실패하면**(06 §6 · §2.5 — 시안이 없다, 06 의 표대로) — 무엇이 안 됐는지 · 서버가 준 문구 그대로 · 할 수 있는 것. 일시적이면 「다시 시도」 · 「버리기」, 입력 문제면 「버리기」만 — 묶음 code 로 고른다(05 §1.2). 요청 중에는 버튼을 잠근다.
    - 다시 시도 → 작업이 기다림으로 돌아가 다시 읽기를 이어 간다.
    - 버리기 → 만들기 전으로 돌아간다(06 §6). 지금은 돌아갈 화면(새로 배우기 · 코스 · 로드맵 · 강의)이 없으니 홈으로 간다 — 뒤 TASK 가 그 화면을 만들면 종류마다 고친다.
    - 다시 시도 · 버리기가 실패하면(크레딧 부족 · 만드는 중인 것이 많음 등) 서버 문구를 그대로 보인다.
- **성공하면 결과 화면으로 저절로 넘어간다**(06 §2.4) — 응답의 결과로 코스 화면 · 로드맵 화면 · 강의 화면의 주소를 정한다. **뒤로 가기를 눌러도 기다리는 화면으로 돌아오지 않게** 기록을 바꿔 넘어간다. 그 세 화면은 아직 없으니 주소만 정하고 자리 화면을 둔다 — 뒤 TASK 가 채운다. 정한 주소를 UI_GUIDE §4.1 주소 표에 더한다.
- **없는 작업**(남의 것 · 지워진 것 — `NOT_FOUND`) · 연결 실패는 무엇이 안 됐는지와 할 수 있는 것(다시 시도 · 홈으로)을 보인다(06 §2.5). 기술 상세는 보이지 않는다.

### 2. API 호출 — `frontend/src/api/`

- 작업 읽기 · 다시 시도 · 버리기를 `apiFetch` 로 부르는 함수 · 훅을 둔다. 응답 타입은 step 3 의 칸 그대로다. 모르는 칸 · 값은 무시한다(05 §1).
- 다시 시도 · 버리기의 응답을 작업 읽기 캐시에 반영한다.

### 3. UI_GUIDE

- 기다리는 화면의 구성 · 상태별 표시 · 주소를 새 절로 적는다. 이 화면에 처음 필요한 컴포넌트(예: 실패 안내)가 생기면 §3 표처럼 적는다 — 화면 하나만을 위한 변형은 만들지 않는다.

### 4. 테스트(Vitest + Testing Library — API 는 흉내 낸다)

- 상태마다 보이는 것 — `QUEUED` · `RUNNING`(종류 셋의 문구) · 새로 배우기의 입력 · 그 밖의 제목.
- 성공이 되면 결과 화면 주소로 넘어가고, 뒤로 가기가 기다리는 화면으로 돌아오지 않는다.
- 실패 — 일시적은 두 버튼, 입력 문제는 버리기만 · 서버 문구를 그대로 · 다시 시도 뒤 다시 읽기 · 버리기 뒤 홈 · 요청 중 버튼 잠금 · 동작 실패 문구.
- `NOT_FOUND` · 연결 실패.
- **보이지 않는 것** — 진행 단계 · 퍼센트 · 남은 시간 · 대기 순서 · 오래 걸릴 때 안내 · 취소가 없다(06 §6). 응답에 모르는 칸이 와도 보이지 않는다.
- 다시 읽기가 성공 · 실패 뒤 멈춘다(가짜 타이머).
- 포커스 · 효과의 결과는 `waitFor` 안에서 단언한다.

## 검증 절차

1. 위 AC 커맨드를 실행한다.
2. 아키텍처 체크리스트를 확인한다:
   - 06 §6 의 보이는 것 · 할 수 있는 것 · 문구가 맞는가? 시안의 구조(영역 순서 · 가장 강조)가 맞는가?
   - 「두지 않는 것」(진행 단계 · 퍼센트 · 남은 시간 · 대기 순서 · 오래 걸릴 때 안내 · 기다리는 동안 복습 · 결과 자리 · 취소)이 없는가?
   - 버튼을 묶음 code 로 고르고 문구는 서버 것을 그대로 쓰는가?
   - 성공하면 기록을 바꿔 넘어가는가?
   - 토큰 밖의 색 · 임의 값 클래스가 없는가(UI_GUIDE §2)?
3. 결과에 따라 `phases/6-job-worker/index.json`의 해당 step을 업데이트한다:
   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약"`. 담을 것: 화면 주소 · 다시 읽는 간격 · 결과 화면 세 주소 · 새 컴포넌트 · 화면 테스트 수(전후)
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 에러 내용"`
   - 사용자 개입 필요 (계약 문서와 코드가 맞지 않음 등) → `"status": "blocked"`, `"blocked_reason": "구체적 사유"` 후 즉시 중단

## 금지사항

- 진행 단계 · 퍼센트 · 남은 시간 · 대기 순서 · 오래 걸릴 때 안내(「혹시 생성이 너무 오래 걸리거나 멈춘 것 같나요?」) · 기다리는 동안 복습하기 · 결과가 들어올 자리 · 만드는 중 취소를 만들지 마라. 이유: 06 §6 「두지 않는 것」 · design README 「06 이 막은 것」.
- 크레딧 · 이 만들기에 드는 크레딧을 보이지 마라. 이유: 크레딧은 내 정보 탭에서만(06 §2.6).
- 결과 화면(코스 · 로드맵 · 강의)의 내용을 만들지 마라. 이유: SCHEDULE §3 상 강의 목록 · 강의 자료 TASK 에서 만든다.
- 홈의 「만드는 중」 · 새로 배우기 화면을 만들지 마라. 이유: SCHEDULE §3 상 홈 · 크레딧 · 강의 목록 TASK 에서 만든다.
- SSE · 웹소켓을 쓰지 마라. 이유: 화면이 작업을 다시 읽는다(04 §1 · ADR-143).
- 06 · 05 의 규칙 문장을 고치지 마라. 이유: phase 전에 정했다. 어긋나면 `blocked`.
- 커밋하지 마라. 이유: Claude 리뷰가 승인한 뒤 하네스가 커밋한다.
- 기존 테스트를 깨뜨리지 마라
