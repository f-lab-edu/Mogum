## 배경

코스 화면(`/courses/:courseId`)을 만든다 — 상태와 상관없이 같은 화면이고 상태마다 보이는 것 · 버튼이 다르다(06 §7). 기다리는 화면이 끝나면 이미 이 주소로 넘어온다.

## 작업

### 1. 상태마다 — 06 §7 의 표

- **검토 중** — 코스 제목 · 강의 목록(강의마다 제목 · 한 줄 설명 · 다룰 개념) · 강의는 아직 열 수 없다는 것.
    - **이대로 시작** — 코스 시작 API. 성공하면 **이 화면이 학습 중으로 바뀐다**(다른 화면으로 가지 않는다 · 1강을 저절로 열지 않는다 — ADR-078). 거절되면(끝나지 않은 다시 짜기 — ADR-182) 서버가 준 문구를 보인다.
    - **다시 짜기** — 고칠 점을 적는 칸(선택 · 500자)을 펼치고 보내면 `POST /api/jobs`(`REPLAN_COURSE`, `courseId`, `feedback`) → 받은 작업의 기다리는 화면으로 간다(ADR-085). 같은 코스의 끝나지 않은 다시 짜기가 있으면 서버가 그 작업을 돌려주므로 그대로 그 기다리는 화면으로 간다. 요청 중에는 버튼을 막는다. 크레딧 부족 · 많음은 서버 문구 그대로.
    - **코스 제목 고치기** — 보이는 이름만(ADR-007). 칸 오류는 그 칸에.
- **학습 중** — 코스 제목 · 강의 목록 · 진도(학습 완료 수 / 전체) · **다음에 열 강의를 눈에 띄게**(ADR-078 · ADR-080) · 코스 제목 고치기.
    - 강의 열기는 이 step 에서 만들지 않는다 — 강의 줄을 누를 수 없게 두고, 다음에 열 강의 표시만 한다(강의 자료 TASK 가 연결한다).
- **다 마침** — 다 마쳤다는 것 · 다 마친 날(한국 날짜 — `Asia/Seoul`) · 코스 제목 · 강의 목록 · 로드맵의 코스면 「로드맵 화면으로 가기」(ADR-101) · 코스 제목 고치기.
- 짜기 전 코스(로드맵 화면에서 오지 않는다)는 따로 그리지 않는다 — 주소로 열리면 로드맵 화면으로 가는 길만 보인다.
- 읽기 실패 · 404 는 무엇이 안 됐나 · 할 수 있는 것을 보인다(06 §2.5) — 지금 공통 방식.
- 학습 중인 로드맵의 코스에서 로드맵으로 가는 길은 두지 않는다 — 다 마친 코스에만(ADR-101).

### 2. 화면 공통

- 시안의 구조(영역 순서 · 가장 강조)를 따르되 공통 컴포넌트 · 토큰으로 맞춘다. 상태 표시(검토 중 · 학습 중 · 다 마침) · 진도 막대처럼 처음 쓰는 것은 공통 컴포넌트로 만들어 UI_GUIDE 에 적는다 — step 9 의 코스 탭 · 로드맵 화면이 다시 쓴다.
- 모구미는 지금 있는 책 읽기 사본만 쓴다. 축하하는 모구미(`mogumi-celebrating`)는 아직 없다(design README 「모구미 이미지」 — 요청 중) — 쓰지 마라.
- 코스 API 를 부르는 도우미는 `frontend/src/api/` 에 두고 TanStack Query 로 캐시한다. 시작 · 제목 고치기 성공 뒤 코스 하나 캐시를 응답으로 바꾼다.

### 3. 테스트 — Vitest + Testing Library

- 상태마다 보이는 것 · 버튼이 06 §7 표와 같다 — 검토 중 · 학습 중 · 다 마침을 따로 시험한다(07 §1 — 상태별로 시험한다).
- 검토 중: 이대로 시작 → 같은 화면이 학습 중이 되고 다른 곳으로 가지 않는다 · 거절 문구 · 다시 짜기 → 보낸 본문(`REPLAN_COURSE` · `courseId` · `feedback`) · 기다리는 화면으로 · 요청 중 버튼 막힘.
- 학습 중: 진도 · 다음에 열 강의 표시 · 강의 줄을 눌러도 아무 데도 가지 않는다 · 다시 짜기 · 이대로 시작이 없다.
- 다 마침: 다 마친 날이 한국 날짜다(UTC 자정 근처 값으로) · 로드맵의 코스만 로드맵으로 가는 길.
- 제목 고치기: 성공 · 칸 오류.
- 포커스 · 효과의 결과는 `waitFor` 안에서 단언한다(S19).

## 검증 절차

1. 위 AC 커맨드를 실행한다.
2. 아키텍처 체크리스트를 확인한다:
   - 06 §7 의 상태별 보이는 것 · 할 수 있는 것 · 두지 않는 것과 맞는가? 시안의 구조를 따르되 공통 컴포넌트로 맞췄는가?
   - 「06 이 막은 것」(시작하면 첫 강의가 열린다는 문구 · 메모 고치기 · 퀴즈 · 지울 때 안내)과 「06 에 없는 것」(강의마다 「핵심 복습 반영」 · 예상 시간 · 수료 배지)이 없는가?
   - 이대로 시작 뒤 같은 화면에 남고 1강을 열지 않는가?
   - 시스템 정보 · 크레딧이 보이지 않는가(금지 20)?
   - `AGENTS.md` 작업 방식(TDD)을 위반하지 않았는가?
3. 결과에 따라 `phases/7-course-planning/index.json`의 해당 step을 업데이트한다:
   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약"`. 담을 것: 화면 · 새 공통 컴포넌트 이름과 경로(step 9 가 쓴다) · API 도우미 · 화면 테스트 수(전후)
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 에러 내용"`
   - 사용자 개입 필요 → `"status": "blocked"`, `"blocked_reason": "구체적 사유"` 후 즉시 중단

## 금지사항

- 강의 열기 · 강의 화면 · 학습 완료를 만들지 마라. 이유: SCHEDULE §3 상 8(강의 자료 · 카드)에서 만든다.
- 「이 코스 복습하기」를 만들지 마라. 이유: SCHEDULE §3 상 9(복습)에서 만든다.
- 코스 지우기를 만들지 마라. 이유: SCHEDULE §3 상 12(지우기 · 탈퇴)에서 만든다.
- 숙련도 반영 내역(몇 개를 짧게 다뤘고 다시 짚었는지)을 만들지 마라. 이유: SCHEDULE §3 상 10(숙련도 고리)에서 만든다.
- 메모 고치기 · 강의 빼기 · 순서 바꾸기 · 강의 제목 고치기 · 진도 되돌리기를 만들지 마라. 이유: 06 §7 두지 않는 것.
- 시안에만 있는 것(「06 이 막은 것」 · 「06 에 없는 것」)을 만들지 마라. 이유: design README — 06 이 정한다.
- 서버 코드(`backend/`)를 고치지 마라. 이유: 이 step 은 화면만이다.
- 커밋하지 마라. 이유: Claude 리뷰가 승인한 뒤 하네스가 커밋한다.
- 기존 테스트를 깨뜨리지 마라
