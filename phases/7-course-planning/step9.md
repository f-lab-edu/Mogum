## 배경

로드맵 화면(`/roadmaps/:roadmapId`)과 코스 탭(`/courses`) · 로드맵 탭(`/roadmaps`)을 만든다. 이것으로 만든 코스 · 로드맵으로 돌아가는 길이 생긴다(README 2026-11-17).

## 작업

### 1. 로드맵 화면 — 06 §8 의 표

- **검토 중** — 로드맵 제목 · 설명 · 계획(코스마다 제목 · 한두 줄 설명 · 다룰 개념).
    - **이대로 시작** — 첫 코스(순서 1)의 `POST /api/jobs`(`PLAN_ROADMAP_COURSE`, `courseId`) → 받은 작업의 기다리는 화면으로 간다(ADR-079 — 로드맵 화면에 남지 않는다). 거절되면(끝나지 않은 계획 다시 짜기 — ADR-182 · 크레딧 부족 · 많음) 서버 문구를 그대로 보인다.
    - **다시 짜기** — 고칠 점(선택 · 500자) → `REPLAN_ROADMAP`(`roadmapId`, `feedback`) → 기다리는 화면(ADR-085).
    - **계획의 코스 제목 고치기** — 보이는 이름만(ADR-009) — step 6 의 코스 제목 고치기 API.
- **진행 중** — 로드맵 제목 · 설명 · 계획과 진행: 코스마다 **짜기 전 · 만드는 중 · 실패 · 만들어짐**(서버가 준 진행 값) · 어느 코스까지 마쳤나.
    - 만들어진 코스 → 코스 화면. 만드는 중 · 실패인 코스 → 서버가 준 작업 ID 의 기다리는 화면(실패면 거기서 다시 시도 · 버리기).
    - **다음 코스 만들기** — 서버가 주면 보인다. 누를 수 없으면 잠긴 채 「앞 코스를 다 마치면 만들 수 있어요」를 함께 보인다(ADR-171). 누를 수 있으면 그 코스의 `PLAN_ROADMAP_COURSE` 받기 → 기다리는 화면.
- **다 마침** — 진행 중과 같이 보이고 다 마쳤다는 것을 함께 보인다. 「다음 코스 만들기」는 없다(ADR-176 · ADR-171).
- 모든 보내기는 요청 중 버튼을 막는다.
- 짜기 전 코스를 무엇이라 보일지 · 진행 표시의 모양은 디자인에 맡긴 것이다(06 §15.3) — 공통 컴포넌트로 단순하게 정하고 UI_GUIDE 에 적는다.

### 2. 코스 탭 · 로드맵 탭 — 06 §12

- **코스 탭** — 코스 목록 API 의 코스(짜기 전 제외 · 로드맵의 코스 포함). 한 줄은 **제목 + 상태(검토 중 · 학습 중 · 다 마침)**(06 §15.1). 누르면 코스 화면. 비면 안내 한 줄(예: 「아직 만든 코스가 없어요」).
- **로드맵 탭** — 로드맵마다 제목 · 설명 · 진행 한 줄(예: 「코스 4개 중 1개 마침」 · 다 마친 로드맵은 「다 마침」 — ADR-176). 누르면 로드맵 화면. 비면 안내 한 줄.
- 두 탭에 새로 배우기 입구를 두지 않는다(design README 「06 에 없는 것」 — 입구는 홈).
- 지금의 자리 화면(`PlaceholderPage`)을 바꾼다.

### 3. 화면 공통

- 시안의 구조(영역 순서 · 가장 강조)를 따르되 step 7 · 8 의 공통 컴포넌트(상태 표시 · 진도 · 입력 · 버튼)를 다시 쓴다. 새로 필요한 것만 더하고 UI_GUIDE 에 적는다.
- API 도우미는 `frontend/src/api/` 에 두고 TanStack Query 로 캐시한다. 코스 제목을 고치면 로드맵 하나 캐시도 맞춘다.

### 4. 테스트 — Vitest + Testing Library

- 로드맵 화면 — 상태마다(검토 중 · 진행 중 · 다 마침) 보이는 것 · 버튼이 06 §8 과 같다.
    - 검토 중: 이대로 시작이 첫 코스의 `PLAN_ROADMAP_COURSE` 를 보내고 기다리는 화면으로 간다 · 거절 문구 · 다시 짜기 본문 · 계획의 코스 제목 고치기.
    - 진행 중: 코스마다 진행 네 가지 · 만들어짐은 코스 화면으로 · 만드는 중 · 실패는 기다리는 화면으로 · 「다음 코스 만들기」 잠김(문구) · 누를 수 있을 때 받기 → 기다리는 화면 · 서버가 주지 않으면 없음.
    - 다 마침: 「다음 코스 만들기」가 없다.
- 코스 탭 · 로드맵 탭 — 한 줄 모양 · 누르면 이동 · 비었을 때 안내 · 새로 배우기 입구가 없다.
- 포커스 · 효과의 결과는 `waitFor` 안에서 단언한다(S19).

### 5. 문서 — 구현으로 정해진 사실만

- `docs/UI_GUIDE.md` — 새 컴포넌트 · §4.1 주소 표의 로드맵 화면 · 코스 탭 · 로드맵 탭 줄(「자리」 → 실제 화면).

## 검증 절차

1. 위 AC 커맨드를 실행한다.
2. 아키텍처 체크리스트를 확인한다:
   - 06 §8 · §12 의 보이는 것 · 할 수 있는 것 · 두지 않는 것과 맞는가? 시안의 구조를 따르되 공통 컴포넌트로 맞췄는가?
   - 「06 이 막은 것」(메모 고치기 · 퀴즈 · 지울 때 안내 · 시스템 정보)과 「06 에 없는 것」(수료증 · 진도율 · 광고 · 상태 거르기 · 정렬 · 탭의 새로 배우기 입구)이 없는가?
   - 이대로 시작 뒤 기다리는 화면으로 가는가? 「다음 코스 만들기」가 잠긴 채 보이는가?
   - 시스템 정보 · 크레딧이 보이지 않는가(금지 20)?
   - `AGENTS.md` 작업 방식(TDD)을 위반하지 않았는가?
3. 결과에 따라 `phases/7-course-planning/index.json`의 해당 step을 업데이트한다:
   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약"`. 담을 것: 화면 · 새 공통 컴포넌트 · 화면 테스트 수(전후)
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 에러 내용"`
   - 사용자 개입 필요 → `"status": "blocked"`, `"blocked_reason": "구체적 사유"` 후 즉시 중단

## 금지사항

- 로드맵 지우기 · 코스 지우기를 만들지 마라. 이유: SCHEDULE §3 상 12(지우기 · 탈퇴)에서 만든다.
- 로드맵 자체의 제목 고치기 · 메모 고치기를 만들지 마라. 이유: 06 §15.1 미정 · ADR-046.
- 진행 중인 로드맵의 계획 다시 짜기 · 다음 코스 저절로 만들기 · 로드맵의 코스 하나만 지우기를 만들지 마라. 이유: 06 §8 두지 않는 것.
- 코스 탭 · 로드맵 탭에 상태 거르기 · 정렬 · 진도 · 새로 배우기 입구를 만들지 마라. 이유: design README 「06 에 없는 것」 — 06 §12 · §15.1 이 정한 것만.
- 홈의 할 일 · 만드는 중 칸을 만들지 마라. 이유: SCHEDULE §3 상 11(홈 · 크레딧)에서 만든다.
- 서버 코드(`backend/`)를 고치지 마라. 이유: 이 step 은 화면만이다.
- 커밋하지 마라. 이유: Claude 리뷰가 승인한 뒤 하네스가 커밋한다.
- 기존 테스트를 깨뜨리지 마라
