## 배경

새로 배우기 화면을 만든다. 서버는 이미 `NEW_COURSE` · `NEW_ROADMAP` 을 받는다(step 3). 받으면 이미 있는 기다리는 화면(`/jobs/:jobId`)으로 가고, 끝나면 기다리는 화면이 코스 · 로드맵 화면으로 넘긴다(이미 있다).

홈은 홈 · 크레딧 TASK(SCHEDULE §3 의 11)에서 생긴다 — 그 전까지 홈 자리(승인된 사람의 `/`)는 임시 화면이다. 새로 배우기의 입구는 홈이므로(06 §5 · ADR-073) **임시 홈 자리에 「새로 배우기」 입구 하나**를 둔다.

## 작업

### 1. 새로 배우기 화면

- 주소를 정한다(예: `/new`) — 승인 뒤 틀(`AppLayout`) 안 · 위 바 제목 「새로 배우기」 · 뒤로 가기.
- 보이는 것(06 §5 · 03 §1.2): 주제(필수 · 직접 입력) · 지금 수준(필수 — 「처음 배워요」 「기초는 알아요」 「익숙해요」 「기타」) · 목적(필수 — 「업무에 쓰려고요」 「면접 준비」 「교양·관심」 「기타」) · 메모(선택) · 로드맵으로 만들기 체크(기본 꺼짐)와 그 옆 설명(06 §5 의 초안 문구).
    - **고르는 것은 버튼으로 나란히** 둔다 — 하나만 고른다(라디오 그룹처럼 접근 가능하게). **미리 골라 둔 값이 없다**(06 §5 두지 않는 것).
    - 「기타」를 고르면 직접 입력 칸이 열린다 — 그때만 보내고 그때는 필수다(05 §2).
    - 체크가 꺼지면 `NEW_COURSE`, 켜면 `NEW_ROADMAP` 이다.
- 할 수 있는 것: 만들기 → 받으면 기다리는 화면으로 간다.
    - **요청 중에는 만들기 버튼을 누를 수 없다** — 연타로 둘이 생기지 않게(README 2026-11-17). 요청이 끝나면(실패면) 다시 누를 수 있다.
    - 길이 상한(주제 100 · 기타 글 50 · 메모 500 — 코드 포인트)은 화면도 같은 값으로 막거나 알린다. 그래도 서버가 기준이다.
- 오류:
    - `FIELD_INVALID` 의 `fields` 를 그 칸 옆에 보인다(05 §1.2 의 `reason` — `REQUIRED` · `TOO_LONG` · `INVALID_VALUE` · `NOT_ALLOWED`).
    - `CREDIT_INSUFFICIENT` · `TOO_MANY_IN_PROGRESS` 는 **서버가 준 문구를 그대로** 보인다(06 §2.5 · ADR-145). 문구를 화면에서 만들지 않는다. 입력은 그대로 남긴다.
    - 그 밖의 실패 · 연결 끊김은 지금 공통 방식(`FailureNotice` 등)으로 — 무엇이 안 됐나 · 할 수 있는 것.
- 두지 않는 것(06 §5): 미리 골라 둔 수준 · 목적 · 강사 고르기 · 기간 · 주당 학습량 · 남은 크레딧 · 이 만들기에 드는 크레딧.

### 2. 임시 홈 자리의 입구

- 승인된 사람의 `/`(지금 `PlaceholderPage`) 에 「새로 배우기」 입구 하나를 더한다 — 누르면 새로 배우기 화면. 홈의 다섯 칸 · 스트릭은 만들지 않는다(홈 TASK).

### 3. 공통 컴포넌트 — 처음 쓰는 것만 더한다

- 시안을 베끼지 않고 `docs/UI_GUIDE.md` 의 토큰 · 컴포넌트로 맞춘다(design README 「시안을 쓰는 법」). 시안의 임의 값 클래스(`text-[11px]` 등)를 옮기지 않는다.
- 이 화면이 처음 쓰는 것 — 글 입력 칸 · 여러 줄 입력 칸 · 고르는 버튼 묶음 · 체크 · 칸 오류 표시 — 를 공통 컴포넌트로 만들고 `docs/UI_GUIDE.md` 에 이름 · 모양 · 상태를 적는다. 다음 step(코스 화면의 다시 짜기 · 제목 고치기)이 다시 쓴다. 화면 하나만을 위한 변형은 만들지 않는다.
- 새 토큰이 필요하면 UI_GUIDE §2 표에 더하고 대비를 §1 방식으로 확인한다.

### 4. 테스트 — Vitest + Testing Library

- 짝 테스트 경로는 `AGENTS.md` 작업 방식을 따른다(`foo.tsx` → 같은 폴더 `foo.test.tsx` 또는 `__tests__/foo.test.tsx`).
- 처음에 고른 값이 없다 · 「기타」를 고르면 칸이 열리고 다시 다른 것을 고르면 닫히고 보내지 않는다 · 체크에 따라 종류가 바뀐다 · 보내는 본문이 05 §2 의 칸 그대로다(쓰지 않는 칸을 보내지 않는다).
- 요청 중 버튼이 막히고 두 번 눌러도 요청이 한 번이다.
- 성공하면 `/jobs/{id}` 로 간다.
- 칸 오류가 그 칸에 · 크레딧 부족 · 많음은 서버 문구 그대로 · 입력이 남는다.
- 임시 홈의 입구가 새로 배우기로 간다.
- 포커스 · 효과의 결과는 `waitFor` 안에서 단언한다(HARNESS-BACKLOG S19 — 한 번씩만 돌면 가끔 실패를 놓친다).

### 5. 문서 — 구현으로 정해진 사실만

- `docs/UI_GUIDE.md` — 새 컴포넌트 · 토큰 · §4.1 화면 주소 표에 새 주소와 임시 홈의 입구.

   - 요청 중 버튼이 막히는가? 오류 문구를 서버에서 그대로 보이는가?
   - 크레딧 · 시스템 정보가 보이지 않는가(금지 20)?

## 금지사항

- 홈의 다섯 칸 · 스트릭을 만들지 마라. 이유: SCHEDULE §3 상 11(홈 · 크레딧)에서 만든다.
- 추천 키워드 · 시안의 수준 「입문 · 초급 · 중급 이상」 · 목적의 「시험 / 자격증 대비」를 만들지 마라. 이유: design README 「06 과 다른 곳」 — 06 · 03 §1.2 를 따른다.
- 남은 크레딧 · 이 만들기에 드는 크레딧을 보이지 마라. 이유: 06 §5 · ADR-113.
- 코스 탭 · 로드맵 탭 · 코스 화면 · 로드맵 화면을 만들지 마라. 이유: step 8 · 9 의 범위다.
- 오류 문구를 화면에서 지어내지 마라. 이유: 문구는 서버가 정한다(ADR-145).
- 서버 코드(`backend/`)를 고치지 마라. 이유: 이 step 은 화면만이다.
- 커밋하지 마라. 이유: Claude 리뷰가 승인한 뒤 하네스가 커밋한다.
- 기존 테스트를 깨뜨리지 마라
