## 배경

코스 · 로드맵 화면과 코스 탭 · 로드맵 탭이 쓸 **읽기 넷과 동작 둘**을 만든다. 만들기는 모두 이미 있는 `POST /api/jobs` 로 받는다 — 로드맵의 「이대로 시작」 · 「다음 코스 만들기」는 `PLAN_ROADMAP_COURSE` 받기, 다시 짜기는 `REPLAN_*` 받기다(05 §2).

**계약 문서는 이 phase 전에 정해 커밋했다(`fa5af24`). 어긋나면 코드를 계약에 맞추고, 맞출 수 없으면 `blocked` 로 멈춰라. 계약 문장을 고치지 마라.** 경로 · 칸 이름 · 오류 code 는 이 step 에서 정해 05 에 적는다(05 §5).

## 작업

### 1. 패키지 — `course` 는 `job` 을 참조하지 않는다

`job` 이 이미 `course` 를 참조한다(`JobReadService` · `JobIntakeService`). 로드맵 하나 읽기(코스마다 만드는 중 · 실패)와 코스 「이대로 시작」(끝나지 않은 다시 짜기)은 작업을 봐야 하지만, **`course` 가 `job` 의 Java 타입을 참조하면 순환이다.** 순환 없이 읽는다 — 예: `course` 의 레포지토리가 `generation_jobs` 를 네이티브 SQL 로 읽어 값만 받는다. `course` → `job` 참조를 막는 ArchUnit 규칙을 더한다.

### 2. 읽기 — `course` 패키지의 컨트롤러 · 읽기 서비스

모두 `@Transactional(readOnly = true)` 의 일반 서비스이고, 주인을 확인해 남의 것 · 없는 것은 `NOT_FOUND`(금지 18). 응답은 객체로 두고 칸을 더할 수 있게 한다(05 §1). 상태 값은 02 §8.7 의 코드 이름 그대로다. 가져오기는 아무것도 바꾸지 않는다.

- **코스 하나** — 코스 ID · 상태 · 제목 · 로드맵의 코스면 로드맵 ID(다 마친 코스의 「로드맵 화면으로 가기」 — ADR-101) · 강의 목록(강의마다 ID · 순서 · 제목 · 한 줄 설명 · 다룰 개념 · 학습 완료 여부) · 진도(학습 완료한 강의 수 / 전체) · 다음에 열 강의(학습 중일 때 — 학습 완료하지 않은 가장 앞 강의) · 다 마친 때(다 마침일 때). 짜기 전 코스는 강의가 없다 — 그대로 읽힌다(로드맵 화면에서 가지 않으므로 화면은 열지 않는다).
- **로드맵 하나** — 로드맵 ID · 상태 · 제목 · 설명 · 코스들(순서대로 — 코스 ID · 순서 · 제목 · 계획의 한두 줄 설명 · 계획의 개념 · 코스의 상태 · **진행**: 짜기 전 · 만드는 중 · 실패 · 만들어짐 — 06 §8) · 「다음 코스 만들기」.
    - 만드는 중 · 실패는 그 코스의 `PLAN_ROADMAP_COURSE` 작업(기다림 · 만드는 중 → 만드는 중, 실패 → 실패)으로 보고, 그 작업 ID 를 싣는다 — 화면이 기다리는 화면으로 간다. 만들어짐은 코스가 검토 중 · 학습 중 · 다 마침인 것이다.
    - 「다음 코스 만들기」 — 로드맵이 진행 중이고 작업 없는 짜기 전 코스가 있으면, 그 가운데 가장 앞 코스의 ID 와 누를 수 있는지(첫 코스이거나 바로 앞 코스가 다 마침 — ADR-018 · ADR-171)를 싣는다. 없으면(마지막까지 만들었거나 다 마침 · 검토 중) 싣지 않는다. 검토 중의 「이대로 시작」 대상(첫 코스 ID)은 코스들에서 화면이 안다.
- **코스 목록**(코스 탭) — 그 사람의 코스 가운데 **짜기 전을 뺀 모두**(단일 코스 + 로드맵의 코스 — ADR-072) · 한 줄은 ID · 제목 · 상태(06 §15.1). 순서는 최근에 만든 것 먼저.
- **로드맵 목록**(로드맵 탭) — 로드맵마다 ID · 제목 · 설명 · 상태 · 진행 한 줄의 재료(다 마친 코스 수 · 전체 코스 수 — 06 §12). 순서는 최근에 만든 것 먼저.
- 목록은 나눠 받지 않는다(05 §5 — 정원 10명).
- 싣지 않는 것 — 입력(주제 · 수준 · 목적 · 메모) · 숙련도 반영 내역(숙련도 고리 TASK) · 이 코스의 오늘 복습할 카드 수(복습 TASK) · 사용자 ID · 시스템 정보(금지 20).

### 3. 동작

- **코스 「이대로 시작」** — 검토 중 → 학습 중 · 시작한 때(`started_at`)를 적는다(02 §8.3). 성공 응답에 코스 하나 읽기와 같은 모양을 돌려주어 화면이 그 자리에서 학습 중으로 바뀐다(ADR-078).
    - **그 코스에 성공하지 않은 코스 다시 짜기(기다림 · 만드는 중 · 실패)가 있으면 받지 않는다**(ADR-182) — 아무것도 바꾸지 않고 오류를 돌려준다. 문구 예: 「다시 짜는 중에는 시작할 수 없어요」 — step 4 가 같은 까닭의 code 를 만들었으면 그것을 쓴다.
    - 이미 학습 중 · 다 마침이면 바꾸지 않고 지금 상태를 돌려준다(연타). 짜기 전이면 거절한다.
    - 같은 코스에 「이대로 시작」과 다시 짜기 받기가 동시에 와도 둘 다 통과하지 않게 한다 — 받기는 사용자 행을 잠근다(`CreditLedger.lock`, 04 §6). 같은 잠금을 먼저 잡는다(금지 11 · 22).
- **코스 제목 고치기** — 단일 코스 · 로드맵의 코스(짜기 전 포함 — 검토 중인 로드맵 계획의 코스 제목 고치기, ADR-009). 상태와 상관없이 고친다(06 §7). 요청 본문을 `@Valid` 로 검사한다 — 빈 글 · 공백만 · 100자(코드 포인트) 초과는 `FIELD_INVALID` 의 칸 오류(02 §8.1 · 금지 25). 성공하면 코스 하나 또는 바뀐 제목을 돌려준다.
- 로드맵 자체의 제목은 고치지 않는다(06 §15.1 — 정하지 않았다).
- 경로 · 메서드는 정한다(예: `GET /api/courses` · `GET /api/courses/{id}` · `POST /api/courses/{id}/start` · `PATCH /api/courses/{id}` · `GET /api/roadmaps` · `GET /api/roadmaps/{id}`). 승인되지 않은 사람은 지금 보안 설정이 막는다(05 §1.1) — 그대로인지 시험으로 본다.

### 4. 테스트

- 컨트롤러 `@WebMvcTest` — 응답 모양 · 칸 오류 · 404 모양.
- 서비스 단위(Fake) — 「다음 코스 만들기」 고르기 · 진행 갈래 · 시작 갈래.
- 통합 `@IntegrationTest`(실제 HTTP · DB):
    - 남의 코스 · 로드맵 · 없는 것은 같은 404 · 아무것도 안 바뀜(07 §1 남의 것).
    - 코스 목록에 짜기 전 코스가 없다 · 로드맵의 코스가 있다.
    - 로드맵 하나 — 코스마다 진행(작업 기다림 · 만드는 중 · 실패 · 성공 뒤 만들어짐) · 「다음 코스 만들기」(앞 코스 학습 중이면 누를 수 없음 · 다 마침이면 누를 수 있음 · 마지막까지 만들면 없음 · 다 마친 로드맵이면 없음).
    - 「이대로 시작」 — 검토 중 → 학습 중 · `started_at` · 끝나지 않은 다시 짜기(기다림 · 만드는 중 · 실패)가 있으면 거절하고 그대로 · 같은 코스에 시작과 다시 짜기 받기가 동시에 와도 둘 중 하나만.
    - 제목 고치기 — 100자 · 101자(코드 포인트) · 공백만 · `updated_at` 이 바뀐다.
    - 승인 전 사람은 막힌다 · CSRF 없는 보내기는 거절된다.

## 금지사항

- 코스 · 로드맵 지우기를 만들지 마라. 이유: SCHEDULE §3 상 12(지우기 · 탈퇴)에서 만든다.
- 강의 하나 읽기 · 학습 완료 · 강의 자료를 만들지 마라. 이유: SCHEDULE §3 상 8(강의 자료 · 카드)에서 만든다.
- 이 코스의 오늘 복습할 카드 수 · 숙련도 반영 내역을 싣지 마라. 이유: 9(복습) · 10(숙련도 고리)에서 더한다 — 응답이 객체라 칸만 더하면 된다.
- 로드맵 제목 고치기를 만들지 마라. 이유: 06 §15.1 에서 정하지 않았다.
- 메모 · 입력을 고치는 길을 만들지 마라. 이유: ADR-041.
- 「진행」 · 「다음 코스 만들기」를 테이블에 저장하지 마라. 이유: 금지 7 — 파생값은 읽을 때 계산한다.
- 작업에 적지 않은 운영 로그 줄(`INFO` 이상)을 더하지 마라. 이유: 줄마다 14일 · 500MiB 보관을 나눠 쓰고, DB 에 남는 사실은 DB 에서 본다.
- 계약 문서(규칙 문장 · ADR · `AGENTS.md` 금지 목록 · README)의 규칙을 고치지 마라. 이유: phase 전에 정해 커밋했다. 어긋나면 `blocked`.
- 커밋하지 마라. 이유: Claude 리뷰가 승인한 뒤 하네스가 커밋한다.
- 기존 테스트를 깨뜨리지 마라
