## 배경

만들기를 받는 순간 거절되는 두 경우 — 크레딧 부족 · 만드는 중인 것이 많음 — 는 실패가 아니라 기다리면 되는 안내다(ADR-116). 지금은 네 곳이 서버 문구를 보이지만 제목이 「…요청하지 못했어요.」이고 「다시 눌러 주세요」 안내가 붙어 있어, 다시 눌러도 같은 안내만 나온다. 이 step 이 06 §2.5 의 공통 안내로 맞춘다.

**계약 문서는 이 phase 전에 정해 커밋했다(06 §2.5 · 05 §1.2). 어긋나면 코드를 계약에 맞추고, 맞출 수 없으면 `blocked` 로 멈춰라. 계약 문장을 고치지 마라.**

## 작업

- 공통 컴포넌트 하나를 만든다(이름 예: `frontend/src/components/CreationBlockedNotice.tsx` + 짝 테스트). 오류가 두 code 중 하나인지 가르는 함수도 함께 둔다.
  - 제목 「지금은 만들 수 없어요」.
  - 그 아래 **서버 문구를 그대로**(05 §1.2 — 크레딧 부족이면 다음에 채워지는 날이 문구에 들어 있다). 화면이 문구를 만들거나 날짜를 붙이지 마라(ADR-145).
  - `CREDIT_INSUFFICIENT` 일 때만 내 정보 탭으로 가는 링크(「남은 크레딧 보기」 등 — 문구 재량).
  - 「다시 눌러 주세요」 같은 다시 하라는 안내 · 「다시 시도」 버튼을 두지 마라(06 §2.5).
  - 오류가 아닌 안내이므로 빨간 오류 제목색을 쓰지 않는다 — 기존 토큰 중 안내에 맞는 것을 고른다(재량, UI_GUIDE 에 적는다). `role` 은 사용자가 누른 직후 나타나는 안내라 읽히게 둔다(`status` 또는 `alert` — 재량, 이유를 summary 에).
- 네 곳(위 '읽어야 할 파일'의 다섯 표시)에서 요청 오류가 두 code 중 하나면 이 안내를, 그 밖의 오류면 지금 표시를 그대로 보인다. 칸 오류(`FIELD_INVALID`) · 그 밖의 묶음의 동작은 바꾸지 마라.
- 강의 화면 — 자료가 없어 화면이 받기를 불렀는데 거절되면 지금은 강의 화면 전체가 실패 안내로 바뀐다. 두 code 면 같은 자리에서 공통 안내와 지금의 「돌아가기」 링크(`back`)를 보인다.

### 시험

- 공통 컴포넌트 — 크레딧 부족: 제목 · 서버 문구 · 내 정보 링크 / 만드는 중인 것이 많음: 제목 · 서버 문구 · 링크 없음 / 「다시」 안내 · 버튼 없음 / code 가 화면에 보이지 않는다(05 §1.4).
- 네 곳 각각 — 두 code 의 가짜 응답이면 공통 안내 · 다른 오류(예: 연결 실패 · `REPLAN_NOT_ALLOWED`)면 지금 표시 그대로.
- 응답을 받은 뒤 그려지는 것은 `findBy…` 뒤 `waitFor` 안에서 단언한다(S19).

## 금지사항

- 만드는 곳에 남은 크레딧이나 이 만들기에 드는 크레딧을 보이지 마라. 이유: ADR-113 · 06 §2.6 — 크레딧은 내 정보 탭에서만.
- 화면에서 두 경우를 미리 막지 마라(크레딧을 먼저 읽어 버튼을 끄는 등). 이유: 서버가 받는 자리에서 판단한다(ADR-104 · 금지 11) — 화면은 거절을 받아 보인다.
- 서버 문구를 화면에서 고쳐 쓰거나 code 별 문구를 화면에 두지 마라. 이유: ADR-145 — 문구는 서버가 정한다.
- 서버(`backend/`)를 고치지 마라. 이유: 두 code 와 문구는 이미 있다(05 §1.2).
- 계약 문서(규칙 문장 · ADR · `AGENTS.md` 금지 목록 · README)의 규칙을 고치지 마라. 이유: phase 전에 정해 커밋했다. 어긋나면 `blocked`.
- 커밋하지 마라. 이유: Claude 리뷰가 승인한 뒤 하네스가 커밋한다.
- 기존 테스트를 깨뜨리지 마라
