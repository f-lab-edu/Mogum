## 배경

이 TASK 의 마지막 step 이다 — **코스 화면에서 강의를 열고, 강의 자료를 만들어 읽고, 학습 완료하는 한 바퀴**를 화면으로 잇는다. 시안은 방향이다 — 베끼지 말고 지금 공통 컴포넌트 · 토큰으로 맞춘다. 화면이 보일 것 · 할 수 있는 것은 06 이 정한다.

## 작업

### 1. 코스 화면에서 강의 열기 — `pages/CoursePage.tsx`

- 학습 중 · 다 마침인 코스에서 **학습 완료한 강의와 다음에 열 강의(`nextLessonId`)만** 강의 화면으로 가는 링크를 단다(ADR-019). 그 뒤의 강의는 열 수 없다는 것이 보이게 두고 링크를 달지 않는다. 검토 중에는 강의를 열 수 없다(지금 그대로).
- 「다음에 열 강의」 칸에서도 그 강의를 열 수 있게 한다(ADR-078).

### 2. 강의 화면 — `/courses/:courseId/lessons/:lessonId`(지금 빈 자리)

강의 하나 읽기 한 번으로 가른다:

- **본문이 있으면** — 강의 제목(몇 번째 강의인지 포함) · step 5 의 본문 컴포넌트 · 아직 학습 완료하지 않았으면 「학습 완료」 버튼, 학습 완료했으면 완료했다는 표시(버튼 없음 — 다시 열어 읽기만).
- **본문이 없고 작업이 있으면** — 그 작업의 기다리는 화면(`/jobs/{id}`)으로 바꿔 간다(`replace` — 뒤로 가기로 빈 강의 화면에 오지 않게). 실패한 작업도 기다리는 화면이 다시 시도 · 버리기를 보인다.
- **둘 다 없으면** — 화면이 `MATERIAL` 받기를 부르고(05 §2), 받은 작업의 기다리는 화면으로 바꿔 간다. 개발 모드의 두 번 실행(React StrictMode)으로 받기가 두 번 가도 서버는 같은 작업을 돌려준다 — 그래도 한 번만 부르도록 막는다(요청 중 표시 등).
- 받기 · 읽기가 거절되면(크레딧 부족 · 만드는 중인 것이 많음 · 열 수 없는 강의) 서버 문구를 그대로 보이고 코스 화면으로 돌아가는 길을 둔다(06 §2.5). 오류 code 를 화면에 보이지 마라(금지 20).
- 기다리는 화면이 끝나면 이 강의 화면으로 저절로 온다(지금 `WaitingPage` 의 `LESSON` 결과 — 고칠 것이 없으면 그대로).

### 3. 학습 완료

- 누르면 학습 완료를 보낸다. 요청 중에는 버튼을 막는다. 되돌리기 확인은 두지 않는다 — 06 §2.7 은 되돌릴 수 없다는 것을 알리라는 뜻이니, 버튼 옆 한 줄 안내로 충분하다(문구는 정한다).
- 성공하면 코스 · 강의 읽기 캐시를 비우고 —
    - 이번 완료로 코스가 다 마침이 됐으면 **축하 화면**으로.
    - 아니면 **코스 화면**으로(진도가 늘고 다음 강의가 다음에 열 강의로 보인다 — ADR-080). 다음 강의를 저절로 열지 않는다.
- 뒤로 가기로 학습 완료 전 화면이 다시 버튼을 보이지 않게 이동은 `replace` 로 한다.

### 4. 축하 화면 — 주소를 정한다(예: `/courses/:courseId/done`)

- 보이는 것 — 모구미(축하 이미지가 아직 없어 `frontend/src/assets/mogumi-reading.png` 사본 · UI_GUIDE §5) · 코스를 마친 것을 알아 주는 문구 하나(코스 제목과 함께 — 「고생했어요」 같은. 코스 제목은 코스 읽기로) · 「홈으로」 버튼(누르면 바로 `/`). 단일 코스 · 로드맵의 코스 모두 같다(06 §15.1).
- 몇 초 뒤 저절로 넘어가지 않는다.
- `docs/design/README.md` 의 「모구미 이미지」 표에서 `mogumi-celebrating.png` 를 쓰는 곳이 축하 화면임을 확인하고, 상태는 「요청」 그대로 둔다.

### 5. 화면 테스트의 옛 오류 code 세 줄

강의 목록 TASK 리뷰에서 넘긴 일이다(README 2026-11-18). `frontend/src/pages/CoursePage.test.tsx:91,98` · `RoadmapPage.test.tsx:79` 의 가짜 응답 code `ROADMAP_REPLAN_IN_PROGRESS` 를 지금 code `REPLAN_IN_PROGRESS` 로 바꾼다. 동작은 바뀌지 않아야 한다.

### 6. 시험(Vitest + Testing Library — `fetch` 가짜)

- 코스 화면 — 학습 완료한 강의 · 다음에 열 강의에만 링크 · 그 뒤 강의는 링크 없음 · 검토 중에는 링크 없음.
- 강의 화면 — 본문이 그려진다 · 학습 완료 버튼 / 완료 표시 · 작업이 있으면 기다리는 화면으로(`replace`) · 둘 다 없으면 받기를 **한 번** 부르고 기다리는 화면으로 · 받기 거절의 서버 문구와 코스로 돌아가는 길.
- 학습 완료 — 요청 중 막힘 · 다 마침이 아니면 코스 화면 · 다 마침이면 축하 화면 · 실패하면 서버 문구.
- 축하 화면 — 코스 제목이 든 문구 · 「홈으로」가 `/` 로.
- 효과의 결과는 `waitFor` 안에서 단언한다. Mermaid 는 step 5 의 방법으로 가짜로 바꾼다.

### 7. 문서 — 구현으로 정해진 사실만

   - 학습 완료 뒤 코스 화면 / 축하 화면으로 가르고 다음 강의를 저절로 열지 않는가?
   - 시스템 정보(오류 code · 모델 · 횟수)를 보이지 않는가? 값이 토큰인가?
   - `AGENTS.md` 금지 목록 · 작업 방식(TDD)을 위반하지 않았는가?
3. 결과에 따라 `phases/8-material-cards/index.json`의 해당 step을 업데이트한다:
   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약"`. 담을 것: 강의 화면 · 축하 화면의 주소와 파일 · 받기를 한 번만 부르는 방법 · 바꾼 옛 code 줄 · 화면 테스트 수(전후)
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 에러 내용"`
   - 사용자 개입 필요 (계약 문서와 코드가 맞지 않음 등) → `"status": "blocked"`, `"blocked_reason": "구체적 사유"` 후 즉시 중단

## 금지사항

- 학습 완료 되돌리기 · 강의 자료 다시 만들기 · 이 강의의 카드 보기 · 첫 복습 · 「카드가 복습에 들어갔어요」 알림 · 이미지를 만들지 마라. 이유: 06 §9 「두지 않는 것」(ADR-012 · ADR-025 · ADR-014 · ADR-080 · ADR-022).
- 시안의 스트릭(「5일 연속 학습 중」 · 「+1일 연장」) · 완주 증서 · 진도 · 「복습 카드 16장 자동 등록」 · 예상 소요 시간 · 파일 이름 · 버전 · 「머금 집중 모드」를 만들지 마라. 이유: design README 「06 이 막은 것」 — 06 §4 · §9 · §10 · ADR-089 · ADR-097.
- 축하 화면에서 몇 초 뒤 저절로 넘어가기 · 「다음 코스 만들기」 버튼을 만들지 마라. 이유: 06 §10.
- 「이 코스 복습하기」 · 복습 탭을 만들지 마라. 이유: SCHEDULE §3 상 복습 TASK(9)에서 만든다.
- 홈을 만들지 마라. 이유: SCHEDULE §3 상 홈 · 크레딧 TASK(11)에서 만든다 — 「홈으로」는 지금 `/` 자리로 간다.
- 모구미 이미지를 그리거나 만들지 마라. 이유: 사용자가 만든다(design README 「모구미 이미지」).
- 커밋하지 마라. 이유: Claude 리뷰가 승인한 뒤 하네스가 커밋한다.
- 기존 테스트를 깨뜨리지 마라
