## 핵심 결정 — 한 줄 이유

| 결정 | 이유 |
|---|---|
| 생성은 **처음부터 비동기 잡**(`jobs` 테이블 = 큐) | 돈이 드는 1분짜리 작업을 한 번만 · 끝까지 하려면 진행 중 작업이 DB 에 있어야 한다 — 중복 방지 · 진행 중 2개 · 단계 재개 · 장애 회수 |
| 큐는 Postgres `SKIP LOCKED` · 저장소는 Postgres 하나 | 우리 요구가 SQL 한 문장에 들어가고, 잡 상태와 산출물이 한 트랜잭션이다. 초당 수백 건이면 틀린 선택 |
| `jobs` 는 JPA 가 아니라 명시적 SQL · 수령 회차 펜싱 | `@Version` 이 정상 실행기의 리스를 매번 깨뜨리는 경로를 설계 점검에서 찾았다 |
| 플랫폼 스레드 · 가상 스레드 미사용 | 오래 기다리는 작업이 실행기 `N` 개로 묶여 이득이 없다(SDK pinning 은 JFR 로 확인했다) |
| **인증은 쿠키 세션 + Spring Session JDBC**(JWT 아님) | 로그아웃 · 탈퇴 즉시 반영과 대기 · 약관 상태 확인 때문에 어차피 요청마다 DB 를 본다 — JWT 의 이점이 없고 코드만 는다. 기기별 로그아웃 · 배포 · 프로세스 분리에도 유지 |
| 단일 모듈 + ArchUnit | 멀티모듈을 부를 계기(배포 단위 · 팀 · 공개 라이브러리)가 없다. 강제 결과는 같다 |
| Spring AI 대신 SDK + 자체 포트 | 재시도 · 리스 갱신을 시도 단위로 쥐어야 리스 부등식이 선다. 프레임워크 안에 숨으면 확인할 수 없다 |
| 채팅 OpenAI(terra · luna) | 한국어를 토큰 절반 가까이로 써서 강의 1건 **82원 vs 162원**, 46~62초 vs 74~90초. 단가표로는 반대 결론이었다. 품질은 블라인드 채점하지 않았다(대가) |
| 임베딩 `text-embedding-3-large` · 임계값 0.46 / 0.78 | 47쌍 · 모델 4개 중 두 분기를 모두 완전히 가른 유일한 모델 |
| 숙련도는 저장하지 않는다 · `R` 과 `S` 의 AND | `R` 은 시간 함수라 저장하면 낡는다. 복습 직후엔 누구나 `R ≈ 1` 이다 |
| 비용은 사후 기록 + 3층 · 레이트리미터 없음 | 초과분이 *진행 중 잡 × 잡 1건 최대비용* 으로 유계 · 실측 토큰으로 한도 여유 약 8배 |
| 분야 무관 · 개념 · 지식형 · 6섹션 고정 | 이름은 고정하고 예시의 모양만 주제가 정한다 |
| 정원제 공개 · 정원 = min(예산, 측정 용량) | 비용이 사용자 수에 비례한다 |

## ⚠️ 확인 필요 — 이 묶음을 만들며 정한 것

> 기획 문서에서 *옛 서사(v1 → v2 → v3) 때문에 들어와 있던 장치*를 걷어내며 아래를 **잠정으로** 정했다. 확인되면 이 절을 지운다.

| # | 정한 것 | 이유 | 되돌린다면 |
|---|---|---|---|
| Q220 | 전역 대기 잡 상한 `Q_max`(503 `QUEUE_FULL`) **제외** | 정원 × 진행 중 2개가 대기 수를 이미 묶는다. 정원은 용량 측정으로 대기가 견딜 만한 값으로 정한다 | 정원을 측정 용량보다 크게 잡을 때 |
| Q221 | **한 프로세스로 운영** · 격리 실험 · 대조 실험 **제외**. 단 **역할 전환(`app.role` = `all` · `api` · `worker`, 기본 `all`)은 비상용으로 넣는다 — ✅ Q233 확정** | 운영이 한 대 · 한 프로세스다. 두 실험은 옛 서사를 위한 것이었다. 역할 전환은 수십 줄로 *장애 때 실행 인자만 바꿔 나누기* 를 산다 | 워커가 API 지연에 영향을 주는 게 관측되면 — 실행 인자만 바꿔 나눈다 |
| Q222 | **선행 생성 · 전경/배경 우선순위 · 승격 제외** → `priority` · `origin` · `promoted_at` 컬럼, 낭비율, 배경 잡 취소가 같이 빠진다 | 25명 규모에서 꼭 필요한지 근거가 없고, 대기 중엔 *"기다리는 동안 복습하기"* 링크가 있다 | 강의 대기 때문에 이탈이 관측될 때 |
| Q223 | 관리자 화면 **U6 유지 · 축소**(미리 만들기 섹션 삭제) | 운영 서버에 Grafana 가 없어 유일한 운영 창이다 | — |
| Q224 | 슬롯 세마포어 삭제 — **실행기 `N` 이 곧 동시 호출 상한** · 모든 LLM 호출에 `JobRef` 필수 | v1 · v2(잡 없는 호출)가 없어졌고, 실행기 ≤ `N` 이면 세마포어는 대기 0 이다 | — |
| Q225 | **`synchronized` 금지 규칙 삭제** | 가상 스레드 pinning 때문의 규칙이었다 | 가상 스레드를 다시 쓸 때 |
| Q226 | 킬스위치는 **적재 전에만** 검사 · 이미 적재된 잡은 끝까지 | 단계 진입 검사는 배경 잡을 멈추려던 것이고 배경 잡이 없어졌다 | 선행 생성을 다시 넣을 때 |
| Q227 | `GET /jobs/{id}` 에서 `tokensUsed` · `estimatedCost` **삭제** | *사용자 응답에 시스템 정보 금지* 규칙과 맞춘다 | — |
| Q228 | 컬럼 추가 — `material.prompt_version` · `material.model` · `curriculum.title` · `lesson.week` | 품질 채점 전후 비교 · 잡 A 출력에 이미 있는 값 | — |
| Q229 | `PROVIDER_SPEND_CAP` 문구를 *"이번 달 마감"* 에서 *"지금은 쓸 수 없어요"* 로 | OpenAI `insufficient_quota` 는 월 단위가 아니라 크레딧 소진이다 | — |
| Q230 | 한도 여유를 실측으로 다시 계산(약 2배 → **약 8배**) · Tier 2 승급은 *필수* 에서 *자연 승급* 으로 | 처음 값은 *호출당 5천 토큰 · 5초* 가정이었다 | — |
| Q231 | 일정은 **주차 대신 순서**로 · 후퇴선 표 삭제 | v1 · v2 구간이 빠져 주차 추정이 무효가 됐다. 기간은 유연 | 다시 추정이 필요하면 12-task-list 에서 |
