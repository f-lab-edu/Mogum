# lecture.json 형식

`scripts/build.py` 가 읽는 내용 파일이다. 페이지 모양은 `assets/player.html` 에 고정되어 있고, 여기에는 내용만 쓴다. 작은 예: `references/example.lecture.json`.

## 맨 위

```json
{
  "title": "만드는 작업과 워커",
  "eyebrow": "머금 · PR #29 · 코드 설명",
  "foot": "코드 발췌는 PR #29 병합 커밋 `887b035` 의 실제 파일에서 줄 번호와 함께 가져왔습니다. ← → 로 넘깁니다.",
  "source": { "rev": "887b035" },
  "snippets": { "...": {} },
  "lists": { "...": {} },
  "chapters": [ {} ],
  "quiz": [ {} ]
}
```

| 칸 | 뜻 |
|---|---|
| `title` | 페이지 제목. 두세 단어에서 한 구절. 브라우저 탭 · 아티팩트 이름이 된다 |
| `eyebrow` | 제목 위 작은 줄 — 프로젝트 · 대상 · 「코드 설명」 |
| `foot` | 맨 아래 한두 문장 — 코드가 어느 커밋 기준인지 반드시 적는다. `` `코드` `` 표기를 쓸 수 있다 |
| `source.rev` | 발췌를 읽을 커밋(짧은 SHA 가능). 없으면 작업 트리 파일을 읽는다 |
| `quiz` | 마지막 장 뒤의 이해도 확인 퀴즈. **필수** — 아래 「quiz」 |

## snippets — 실제 파일에서 자를 코드

키는 단계가 `code` 로 부르는 이름이다. 두 방법 중 하나로 자른다.

```json
"claim": { "file": "backend/src/main/java/com/mogum/worker/JobRunner.java", "from": "private JobSnapshot claim", "to": "^    }$" },
"yml":   { "file": "backend/src/main/resources/application.yml", "lines": [12, 30] },
"other": { "file": "...", "from": "...", "to": "...", "rev": "abc1234" }
```

- `from` · `to` — 정규식. `from` 에 처음 맞는 줄부터, 그 뒤 `to` 에 처음 맞는 줄까지(포함). 메서드 하나는 `"to": "^    }$"`(들여쓰기 4칸의 닫는 괄호)가 잘 맞는다.
  - `to_exclusive: true` — `to` 줄과 그 앞 빈 줄을 뺀다(다음 메서드 시작을 `to` 로 줄 때).
  - `from_offset: -1` — 시작을 위로 한 줄 넓힌다(애노테이션 · 주석 포함).
- `lines: [시작, 끝]` — 1부터 센 줄 번호(포함). 그 rev 의 파일을 읽어 번호를 확인한 뒤 쓴다.
- `rev` — 이 발췌만 다른 커밋에서 읽는다(예: 바뀌기 전 코드와 비교).
- 정규식이 함수 이름 하나로 끝나면 같은 이름의 다른 메서드에 먼저 맞을 수 있다 — `public JobResult receive` 처럼 앞을 붙인다.
- 한 발췌는 단계들이 가리킬 범위만 — 대개 10~60줄. 긴 메서드는 둘로 나눠도 된다.
- 언어 색칠은 확장자로 정한다: java · kt · sql · yml · ts/tsx/js · py. 나머지는 글자 그대로.

## lists — 코드 칸에 띄우는 요약 목록

```json
"order": { "title": "직접 읽을 때의 순서", "items": ["`V11__create_generation_jobs.sql` — 표부터", "`JobIntakeService` — 받기"] }
```

단계에서 `"code": "list:order"` 로 부른다. 첫 장(무엇을 다루나) · 마지막 장(읽는 순서)에 쓴다. `hl` 은 쓰지 않는다.

## chapters — 장

```json
{
  "title": "작업 집기",
  "kind": "background",
  "nodes": [ ... ],
  "edges": [ ... ],
  "beats": [ ... ]
}
```

장마다 도식 하나. 장 안의 단계들은 같은 도식에서 강조만 바꾼다.

- `kind: "background"` — 이 저장소의 코드가 아니라 개발자로서 알아 둘 개념을 다루는 **배경 지식 장**. 장 목록과 단계 머리에 「배경 지식」이 붙는다. 코드 장이면 `kind` 를 쓰지 않는다. 배경 장도 `code` 로 발췌를 띄울 수 있다(그 개념이 코드에서 쓰이는 곳).

### nodes — 도식의 상자

도식 영역은 **640 × 380** 이다. 상자가 영역 밖으로 나가면 조립이 멈추고, 겹치면 경고가 난다.

```json
{ "id": "worker", "x": 492, "y": 150, "w": 132, "h": 64, "k": "svc", "l": "워커", "s": "JobRunner × 2" }
```

| 칸 | 뜻 |
|---|---|
| `id` | 장 안에서 유일. 단계의 `on` 이 부른다 |
| `x` `y` `w` `h` | 왼쪽 위 좌표와 크기. 보통 w 104~170 · h 40~70 |
| `k` | 종류(아래 표). 없으면 `svc` |
| `l` | 큰 이름(한국어 뜻). `\n` 으로 줄 바꿈 |
| `s` | 작은 글씨(코드 이름 · 표 이름 · 값). `\n` 가능 |
| `m: true` | `l` 을 고정폭 글꼴로(코드 이름이 큰 이름일 때) |
| `i: true` | 한 줄 배치 — 왼쪽에 `l`, 오른쪽 끝에 `s`(시간 막대 · 목록형 상자) |
| `align` | `cap` 만 — `start` · `middle` · `end` |

| `k` | 생김새 · 쓰는 곳 |
|---|---|
| `svc` | 기본 상자 — 클래스 · 서비스 · 화면 · 상태 |
| `db` | 파란 채움 — 표 · 저장소 |
| `ext` | 점선 — 바깥 서비스(OpenAI · 구글) |
| `ok` · `err` | 초록 · 빨강 — 성공 · 실패 결과, 거절 |
| `note` | 옅은 점선 — 곁말 · 출발점 |
| `later` | 흐린 점선 — 아직 없는 것 · 다음 TASK |
| `box` | 큰 점선 틀 — 트랜잭션 · 경계 묶음. 제목은 왼쪽 위. 다른 상자보다 먼저 그린다 |
| `held` · `free` · `slack` | 시간 막대 — 쥔 구간 · 놓은 구간 · 여유 |
| `cap` | 글자만(행 · 열 제목). `x` `y` 는 글자 기준선 |

배치 요령: 흐름은 왼쪽 → 오른쪽 또는 위 → 아래로 한 방향. 상자 사이는 24 이상 띄워 선 이름이 들어갈 자리를 둔다. 한 장에 상자 9개 이하. 시간 순서를 보여 줄 때는 `i` 상자를 실제 비율의 너비로 늘어놓는다.

### edges — 선

```json
{ "f": "jobs", "t": "worker", "l": "집기" }
{ "f": "R_IN", "t": "R_DONE", "l": "마지막 코스", "k": "dash" }
{ "id": "rloop", "d": "M 216 60 C 206 22, 262 22, 252 60", "l": "다시 짜기", "lx": 234, "ly": 22 }
```

- 선 id 는 `f-t`(예: `jobs-worker`). 같은 두 상자 사이에 선이 둘이면 `id` 를 따로 준다.
- 곧은 선은 두 상자 가장자리를 잇는다. 고리 · 꺾인 선은 SVG 경로 `d` 와 이름 위치 `lx` `ly` 를 직접 준다.
- `k`: 없음(실선) · `dash`(일어날 수도 있는 흐름) · `err`(실패 흐름) · `mark`(화살표 없는 점선 표시).

### beats — 단계

```json
{
  "say": "워커는 작업을 집는 순간 claim_count 를 1 올립니다.",
  "detail": [
    "첫 문단 …",
    ["목록 항목 1", "목록 항목 2"],
    "둘째 문단 …"
  ],
  "refs": ["AGENTS 금지 9", "ADR-126"],
  "on": ["worker", "jobs"],
  "e": ["jobs-worker"],
  "code": "claim",
  "hl": ["claim_count = j.claim_count + 1"],
  "know": {
    "title": "Postgres 의 SKIP LOCKED",
    "body": ["문단 …", ["목록 1", "목록 2"]]
  }
}
```

| 칸 | 뜻 |
|---|---|
| `say` | 이 단계의 요점 한두 문장. 굵게 크게 보인다 |
| `detail` | 자세한 설명. 문자열은 문단, 문자열 배열은 글머리 목록. **필수** |
| `refs` | 근거 꼬리표 — 금지 번호 · ADR · 문서 절 · 테스트 이름. 선택 |
| `on` | 강조할 상자 id. 하나라도 있으면 나머지는 흐려진다 |
| `e` | 강조할 선 id(흐르는 점선이 된다) |
| `code` | snippets 키 · `list:키` · `null`(코드 없음) |
| `hl` | 강조할 줄을 찾는 **부분 문자열** 목록. 그 문자열을 포함한 줄이 모두 강조된다 |
| `know` | 「더 알아두기」 상자 — 설명 · 근거 꼬리표 아래 파란 상자로 보인다. `title`(개념 이름)과 `body`(`detail` 과 같은 모양)가 모두 있어야 한다. 선택 |

- `code` 를 적지 않은 단계는 같은 장 앞 단계의 `code` 와 `hl` 을 이어 쓴다. `hl` 만 바꾸려면 `hl` 만 적는다.
- `hl` 은 실제 줄에 있는 글자여야 한다 — 없으면 조립이 멈춘다. 너무 흔한 문자열(`}` · `return`)은 여러 줄을 칠하니 그 줄에만 있는 조각을 고른다.
- 글 안 표기: `` `코드` `` → 고정폭, `**강조**` → 굵게. 그 밖의 HTML 은 글자 그대로 보인다.

## quiz — 이해도 확인

마지막 장 뒤에 퀴즈 화면이 하나 붙는다(장 목록 · 진행 막대 끝의 「퀴즈」). 문항은 객관식과 서술형 두 종류다 — `choices` 가 있으면 객관식, `model` 이 있으면 서술형이고 둘을 함께 쓰지 않는다.

```json
"quiz": [
  {
    "q": "시한이 지나 워커 B 가 같은 작업을 다시 집었습니다. 누가 지금 주인인지 가려 주는 값은?",
    "choices": ["`status`", "`claim_count`", "`lease_until`", "작업 `id`"],
    "answer": 2,
    "why": ["정답의 이유와 헷갈리는 보기가 왜 틀렸는지 …"],
    "see": [1, 2]
  },
  {
    "q": "`guard` 를 트랜잭션의 마지막 쓰기로 옮기면 무엇이 깨지나요?",
    "model": ["모범 답 문단 …"],
    "points": ["이게 들어 있으면 맞은 것 1", "2"],
    "see": [3, 1]
  }
]
```

| 칸 | 뜻 |
|---|---|
| `q` | 질문. `` `코드` `` · `**강조**` 표기를 쓸 수 있다. **필수** |
| `choices` | 객관식 보기 3~5개 |
| `answer` | 객관식 정답 번호 — **1부터** 센다 |
| `why` | 객관식 해설(`detail` 과 같은 모양). 답을 고르면 맞음 · 틀림과 함께 보인다. 객관식에 **필수** |
| `model` | 서술형 모범 답(`detail` 과 같은 모양). 「모범 답 보기」를 누르면 보인다 |
| `points` | 서술형 채점 기준 — 「이게 들어 있으면 맞은 것」 목록. 선택이지만 쓰는 편이 스스로 채점하기 쉽다 |
| `see` | 다시 볼 단계 `[장, 단계]` — **1부터** 센다. 문항마다 「다시 보기」 링크가 그 단계로 보내고, 「퀴즈로 돌아가기」로 돌아온다. **필수** |

- 객관식은 고르는 순간 채점되고 다시 고를 수 없다(「다시 풀기」로 모두 지운다). 서술형은 내 답을 쓰고 → 모범 답을 펴고 → 「맞았다 · 부족했다」로 스스로 채점한다. 고른 답 · 쓴 답은 그 브라우저에만 남는다.
- 경고: 서술형이나 객관식이 하나도 없을 때, 객관식 정답 번호가 모두 같을 때(3문항 이상).
